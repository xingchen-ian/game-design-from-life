## 1. 课程定位与核心理念

### 1.1 四步法（课程的方法论主轴）
所有项目都贯穿同一条思维链（方法贯通，代码不贯通）：

```
① 一个生活/学习感受（情感原型）
        ↓ 引导式问答系统化
② 一个被数据化的抽象系统（动作 / 过程 / 空间 / 数据）
        ↓ 编程搭建
③ 基于 Unity 的系统搭建（C# 实现核心玩法）
        ↓ 拓展
④ 游戏体验与游戏世界的拓展
```

### 1.2 AI Agent 时代的技能定位
- AI 是**设计伙伴、编程助手、资产工厂**，不是替代思考的捷径
- 学生必须学会：向 AI 描述需求、批判评估 AI 输出、理解并修改 AI 生成内容
- 考核从"会不会做"转向"创意 + AI 协作能力"

### 1.3 三个独立 Game，方法论贯通
| Game | 类型 | 技术栈 | 训练重点 |
|------|------|--------|---------|
| Game One | 框架生成游戏 | 纸面 / 引导式问答（无代码） | 设计思维、抽象 |
| Game Two | 游戏世界 | 团结引擎（Unity 2022 LTS）单人体验 | 工程、C# |
| Game Three | 多人游戏 | 团结引擎 + 服务器 | 系统、联机、社交 |

> **为什么独立而非贯穿**：Game One 为 web/纸面、Game Two 为 Unity，硬贯通有迁移成本；
> Game Three 从物理原型起步（非继承 Game Two 世界），自成脉络。独立让每段干净聚焦，
> 四步法作为统一主线把三段串起来。

## 3. 三段 Game 详细设计

### Game One — 游戏框架生成游戏（C1–C3，约 2 周）
**流程**：采用暑期课程流程 —— **用引导式问答的方式做出游戏原型**。
将"一个领域知识的学习体验"通过一系列问题系统化为可玩原型。

- **输入**：学生选择一个领域知识 / 学习体验作为原型来源
- **方法**：引导式问答（动作 / 过程 / 空间 / 数据 四要素）逐步抽象为机制
- **产出形态**：纸面 / 工作坊原型（**不写代码**）
- **AI 落点**：C2 用 ChatGPT 类工具辅助头脑风暴、批判设计建议
- **验证**：C3 用户测试重点做"情感等价验证"（玩家是否体验到目标感受）

> 设计意图：刻意保持低技术，逼学生专注设计思维；为 Game Two 引入 Unity 复杂度铺垫。

### Game Two — 游戏世界（C4–C7）
**目标**：在团结引擎中用 C# 把情感原型搭成可玩的单人体验世界。

- **C4 Unity Basics**：编辑器、GameObject/Component、场景；团结引擎安装（勾选 WebGL + 微信小游戏模块）
- **C5 coding basics**：C# 变量 / 条件 / 循环 / MonoBehaviour；用 Copilot 辅助生成并理解代码
- **C6 Features**：物理系统、玩家控制、UI 与数据可视化
- **C7 User test**：用 **WebGL 构建**在浏览器试玩（避开微信所有坑，人数无限）
- **AI 落点**：C4–C5 编程助手；C6 AIGC 美术初探

### Game Three — 多人游戏（C8–C11）
**目标**：从社交机制观察出发，做出可联机的数字游戏。

- **C8 Board Club Field Trip**：实地考察，观察真实桌游的社交 / 多人机制
- **C9 Physical Prototype**：把多人规则做成桌面前置原型；AI 测规则漏洞
- **C10 Unity Demo**：在 Unity 实现多人；AIGC 资产 + NPC 对话
- **C11 User Test**：联机测试，定稿服务器方案
- **服务器方案**（详见 §5.3）

### Finals — 优化与展示（C12–C14）
- **C12 Optimization 1**：WebGL 发布初稿 + AI 优化建议
- **C13 Optimization 2**：终稿发布（WebGL 上线 + 可选微信体验版 / 云托管）
- **C14 Final Presentation**：展示 + AI 协作反思报告

## 5. Unity / 团结引擎与发布路径

### 5.1 为什么用团结引擎
- Unity 国际版 2025 起不再向中国用户提供，海外 Asset Store 自 2026-03-31 起不可访问
- Unity Educator Plan **不向中国大陆提供**
- **团结引擎**（优三缔科技）基于 **Unity 2022 LTS**，C# 代码完全兼容，是合法本地化路径
- 下载：https://unity.cn/tuanjie/releases ｜ 安装时勾选 **WebGL Build Support** 与 **Mini Game Build Support**

### 5.2 WebGL 与微信小游戏的关系
- 两者是**两套独立构建目标**；装齐模块后通过 Build Settings → Switch Platform 切换
- 切换触发全量重编译；微信端还需菜单「微信小游戏 → 转换小游戏」
- **引擎自动做底层移植**（重编译、资源加载链重写、包体精简）；**手动补配置层**：
  - 颜色空间必须设 **Gamma**（否则微信真机渲染空白）
  - 微信主包 **≤ 4MB**（资源走 CDN / Auto Streaming）
  - 平台专属代码用 `#if UNITY_WEIXINMINIGAME` / `#if UNITY_WEBGL` 宏隔离
  - 微信 SDK（登录 / 分享 / 广告 / 排行榜）需自行接入
- **推荐工作流**：整学期用 WebGL 开发 + 浏览器试玩；最后两周切微信平台 + 转换 + 补配置

### 5.3 多人游戏服务器方案
WebGL 在浏览器**无原生 socket**，只能用 WebSocket / WebRTC，且 **WebGL 实例不能当 host**，
必须有一个独立运行的服务器。

| 方案 | 是否需要托管 | 备注 |
|------|------------|------|
| 托管型中继（Photon / Unity Gaming Services Distributed Authority，有免费额度） | 服务商托管 | 最省事，学生接 SDK |
| 自建 WebSocket 服务（轻量 VPS） | 自己租云 | 无 ICP 负担（浏览器不强制备案），可放海外 |
| WebRTC P2P | 仍需轻量信令服务器 | 玩家直连省游戏服务器 |

**微信端联机**：用**微信云托管**免域名备案（绕开个人 ICP 必拒的死路）。

### 5.4 发布阶梯（按强制条件）
| 状态 | 双备案 | 审核 | 谁能玩 | 课程用途 |
|------|--------|------|--------|---------|
| 开发版预览 | 否 | 否 | 仅开发者 | 自测 |
| 体验版（设体验版 + 加成员） | 否 | 否 | ≤15 人（个人主体） | 课堂小范围试玩 |
| WebGL 浏览器版 | 否 | 否 | 人数无限 | **课堂试玩会（推荐）** |
| 正式上线 | 是（双备案） | 是 | 任何人 | 高阶选修，需提前 2–4 周启动 |

> 主线交付：**可玩 WebGL 版 + 可选微信体验版**。双备案仅作高阶挑战。
