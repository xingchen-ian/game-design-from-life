# 情感原型库

本文件记录"来自生活的游戏设计"方法论中的核心情感原型。

## 什么是情感原型

情感原型是生活中反复出现的、具有普遍共鸣的情感模式。它们是连接"生活体验"与"游戏体验"的桥梁。

情感原型库不是情绪词表，也不是封闭的分类体系。它记录的是一种情感在生活中如何发生、如何展开、如何被游戏机制重新组织。原型库的核心价值在于帮助设计师从情感结构反推机制，而不是穷尽所有可能的情感。

## 情感原型记录模板

新增或修订一个情感原型时，建议使用以下模板：

| 字段 | 记录内容 |
|------|---------|
| 原型名称 | 中文名 + 英文名 |
| 生活情境 | 这个情感通常出现在什么真实生活场景中？ |
| 触发条件 | 什么条件会引发这种情感？ |
| 核心张力 | 当事人想要什么？什么阻止了他？ |
| 情感轨迹 | 情绪如何从开始、转折、高峰走向余韵？ |
| 可机制化变量 | 哪些要素可以转成时间、距离、资源、状态、关系等变量？ |
| 机制转译策略 | 可以用哪些玩家输入、挑战、规则和反馈重现情感结构？ |
| 验证方式 | 试玩或访谈中，如何判断玩家感受到了相似情感？ |
| 迭代记录 | 玩家反馈或课堂实践如何修正了这个原型？ |

## 核心情感原型

### 1. 绝处逢生 (Against All Odds)

**生活场景**：
- 考试前夜突击复习，意外通过
- 创业濒临破产，最后一搏成功
- 绝境中找到意想不到的出路

**核心情感**：
- 紧张 → 绝望 → 希望 → 狂喜
- 压力释放的快感
- 自我效能感的提升

**游戏转化**：
- **输入设计**：资源极度匮乏，时间压力
- **挑战设计**：高难度但可克服的障碍
- **机制示例**：
  - 血量/资源极低时的"背水一战"机制
  - 随机事件提供转机
  - 风险与收益的极端不对称

**设计要点**：
- 必须让玩家感受到"真正的危险"
- 转机不能过于随机，需要玩家行动触发
- 成功后的奖励要足够强烈

---

### 2. 三顾茅庐 (Persistent Effort)

**生活场景**：
- 反复尝试后终于成功
- 坚持追求最终获得认可
- 多次失败后的突破

**核心情感**：
- 挫败 → 坚持 → 怀疑 → 突破 → 成就感
- 过程中的成长感
- 努力被认可的满足感

**游戏转化**：
- **输入设计**：多次尝试的机制，渐进式难度
- **挑战设计**：需要学习和适应的挑战
- **机制示例**：
  - Roguelike的永久进步机制
  - 技能树的逐步解锁
  - NPC关系度的逐步建立

**设计要点**：
- 每次失败都要有收获
- 进步需要可见可感
- 最终成功要配得上付出的努力

---

### 3. 遗憾 (Regret)

**生活场景**：
- 错过机会的后悔
- 选择后的"如果当初"
- 无法挽回的失去

**核心情感**：
- 失落、 nostalgia、反思
- 对选择的重新思考
- 珍惜当下的领悟

**游戏转化**：
- **输入设计**：不可逆的选择
- **挑战设计**：资源/时间的有限性
- **机制示例**：
  - 分支叙事中的重大选择
  - 时间限制导致的取舍
  - 永久死亡机制

**设计要点**：
- 选择必须真正有意义
- 遗憾不能过于沉重，要转化为反思
- 可以设计"弥补"机制，但要有代价

---

### 4. 惊喜 (Serendipity)

**生活场景**：
- 意外发现的美好
- 无心插柳柳成荫
- 巧合带来的愉悦

**核心情感**：
- 好奇、愉悦、感恩
- 世界充满可能性的感觉

**游戏转化**：
- **输入设计**：探索机制，隐藏内容
- **挑战设计**：非线性的发现路径
- **机制示例**：
  - 隐藏关卡/彩蛋
  - 随机但有益的遭遇
  - 意外组合产生的协同效果

**设计要点**：
- 惊喜要合理，不能太随意
- 玩家行为应该增加惊喜的概率
- 惊喜内容要有价值

---

## 情感原型的设计流程

```
┌─────────────────┐
│  观察生活体验    │
│  (设计师的敏感度) │
└────────┬────────┘
         ↓
┌─────────────────┐
│  提取情感核心    │
│  (什么情感？为什么强烈？)│
└────────┬────────┘
         ↓
┌─────────────────┐
│  分析情感结构    │
│  (前因→情感→后果)│
└────────┬────────┘
         ↓
┌─────────────────┐
│  转化为游戏语言  │
│  (输入+挑战+反馈)│
└────────┬────────┘
         ↓
┌─────────────────┐
│  原型测试与迭代  │
│  (情感是否被重现？)│
└─────────────────┘
```

## 使用指南

设计游戏时：
1. 先记录具体生活体验，不要直接从抽象情绪词出发。
2. 分析触发条件、核心张力、情感轨迹和余韵。
3. 判断是否能参考已有原型；不能匹配时，创建新的原型候选。
4. 将情感结构转译为玩家输入、挑战、变量、规则和反馈。
5. 通过试玩、访谈或课堂讨论测试情感是否被传达。
6. 根据反馈修正原型描述，并记录文化差异或玩家差异。
