# 从领域学习到游戏系统

> **文档性质**：`来自生活的游戏设计` 总方法论下的领域学习路径  
> **用途**：面向高中生夏令营、工作坊和后续研究分析  
> **版本**：v0.1  
> **最后更新**：2026-07-05

---

## 1. 分支定位

“从领域学习到游戏系统”不是对“来自生活的游戏设计”的替代，而是它在**领域学习经验**上的一条转译路径。

更准确地说，“来自生活的游戏设计”是总方法论：

```text
真实生活经验
├── 情感经验路径：生活事件 → 情感结构/情感原型 → 挑战空间设计 → 游戏机制
└── 领域学习路径：领域学习 → 认知/技能结构 → 挑战空间设计 → 游戏机制
```

原方法的常见路径是：

```text
生活事件 → 情感结构 → 游戏机制
```

本路径关注另一类真实生活经验：

```text
领域学习体验 → 新手/高手认知差异 → 技能与反馈结构 → 挑战空间设计 → 游戏机制
```

它仍然来自生活，但重点不再只是“我经历了什么情感”，而是“我如何进入一个真实领域，并逐渐学会用这个领域的方式感知、判断和行动”。

适合本分支的领域包括但不限于：

- 驾驶帆船
- 攀岩
- 摄影
- 急救
- 咖啡萃取
- 舞台灯光
- 城市骑行
- 篮球战术
- 天文观测
- 植物养护
- 机器人调试

## 2. 与原方法的关系

### 2.1 继承

本路径继承总方法论的四个基本判断：

1. 游戏设计不应从现成游戏类型开始，而应从真实经验结构开始。
2. 游戏不是现实模拟，而是对现实经验的抽象、结构化、放大和安全容器化。
3. 好的转译必须落到玩家输入、挑战、变量、规则和反馈。
4. 原型测试的重点不是“像不像现实”，而是玩家是否经历了相似的结构。

### 2.2 不同

情感经验路径主要以情感结构为桥梁：

```text
现实体验中的情感轨迹 → 游戏中的情感等价
```

本路径以认知和技能为桥梁：

```text
学习某个领域时的认知变化 → 游戏中的技能习得过程
```

因此，本路径的核心问题不是“玩家是否感受到我的情绪”，而是：

> 玩家是否开始像这个领域中的学习者一样观察、判断、行动和修正？

## 3. 核心概念

### 3.1 领域学习体验

指学习者进入一个真实知识或技能领域时经历的过程。它包括知识、动作、工具、环境、限制、失败、反馈和熟练化。

### 3.2 新手/高手认知差异

新手和高手看到的是同一个世界，但读取方式不同。新手看到表面对象，高手看到关系、限制、风险和反馈。

示例：

| 领域 | 新手以为 | 高手知道 |
| --- | --- | --- |
| 帆船 | 我要控制船 | 我要读取风，并调整船与风的关系 |
| 攀岩 | 我要用手把自己拉上去 | 我要读路线、用脚、保存体力、控制重心 |
| 摄影 | 我要拍清楚 | 我要控制光线、曝光、构图和观看顺序 |
| 咖啡 | 我要照配方操作 | 我要根据研磨、流速和味道反馈调整参数 |

### 3.3 技能循环

每个领域都可以拆成一个学习循环：

```text
观察 → 判断 → 行动 → 反馈 → 调整 → 熟练
```

游戏机制应尽量围绕这个循环建立，而不是只把领域知识做成题目或装饰。

### 3.4 领域反馈

领域反馈是学习者判断自己是否做对的信号。它可能来自身体、工具、环境、他人或系统结果。

例如：

- 帆船：风向、帆的形状、船速、倾斜、航线偏差
- 攀岩：手臂疲劳、脚点稳定性、身体重心、下一步是否可达
- 摄影：曝光、阴影、构图平衡、主体是否突出
- 急救：呼吸反应、出血变化、时间压力、环境安全

## 4. 七步流程的分支改写

### Step 1：领域学习采样

**目标**：选择一个真实学习领域，并描述自己或他人进入这个领域的过程。

输出：

- 领域名称
- 学习场景
- 新手最初的理解
- 第一次明显失败或卡住的时刻
- 学会一点之后看到的新东西

### Step 2：认知结构与技能结构

**目标**：找出这个领域中的新手/高手差异、核心挑战和反馈信号。

输出：

- 新手误解
- 高手判断方式
- 核心技能循环
- 关键反馈信号
- 最常见错误

### Step 3：数据化抽象

**目标**：把领域中的限制、资源、反馈和行动转成变量。

常见变量类型：

| 类型 | 示例 |
| --- | --- |
| 环境变量 | 风向、坡度、光线、噪声、温度 |
| 身体变量 | 体力、平衡、压力、注意力、疲劳 |
| 工具变量 | 帆角、绳索张力、镜头参数、设备状态 |
| 信息变量 | 可见线索、未知风险、经验记忆 |
| 成长变量 | 熟练度、识别能力、动作准确度 |

### Step 3.5：领域系统结构图

**目标**：把领域对象、玩家行动、反馈信号和资源状态画成图。

推荐四列：

```text
领域对象 → 玩家行动 → 反馈信号 → 资源/状态
```

示例：

```text
风向 / 帆 / 船体 → 调帆 / 转向 → 船速 / 倾斜 / 偏航 → 动能 / 风险 / 航线
```

### Step 4：挑战空间设计

**目标**：从领域系统因素中推导出多样化挑战，而不是靠灵感临时想关卡。

本步骤的核心问题是：

> 哪些领域因素改变后，会迫使玩家学习新的判断方式？

**挑战设计公式**：

```text
领域挑战 = 系统因素的特定组合 + 对领域能力的特定要求
```

**过程**：

1. **列出领域因素**：先尽可能列出会影响行动和反馈的真实因素。

以驾驶帆船为例：

- 风向
- 风力
- 阵风变化
- 浪高
- 浪向
- 洋流方向
- 洋流强度
- 礁石大小
- 礁石数量
- 礁石分布
- 礁石类型
- 能见度
- 航道宽度
- 目标位置
- 时间压力
- 船体状态

2. **筛选挑战因素**：不是所有因素都值得进入游戏。用以下问题筛选：

| 筛选问题 | 判断标准 |
| --- | --- |
| 是否改变玩家决策？ | 如果风力变化不影响操作，它只是背景。 |
| 是否能被玩家感知？ | 玩家要能通过帆、船速、倾斜、仪表、声音或画面读到它。 |
| 是否改变反馈？ | 同样转向，在洋流中和无洋流中结果不同，才有设计价值。 |
| 是否能形成难度层级？ | 从弱风到强风、从稀疏礁石到密集礁石。 |
| 是否对应领域能力？ | 它应考验读风、预判、借力、路线规划，而不是无关反应。 |

3. **建立挑战维度表**：

| 系统因素 | 简单状态 | 困难状态 | 形成的挑战 | 训练/考验的能力 |
| --- | --- | --- | --- | --- |
| 风向 | 顺风/侧风 | 目标在逆风方向 | 不能直线抵达目标 | 读风与规划航线 |
| 风力 | 稳定中等风 | 弱风/强风/阵风 | 船速不足或失控 | 调帆与风险控制 |
| 洋流 | 无明显洋流 | 横向强流 | 航线持续偏离 | 提前补偿判断 |
| 礁石数量 | 稀疏 | 密集 | 安全路径变窄 | 路径规划 |
| 浪高 | 平稳 | 剧烈 | 操作反馈延迟 | 稳定控制 |
| 能见度 | 清晰 | 雾天 | 信息不完整 | 谨慎探索 |

4. **设计挑战组合表**：

| 挑战名称 | 变量组合 | 玩家要面对的局面 | 训练/考验的能力 |
| --- | --- | --- | --- |
| 稳定侧风 | 中等风 + 开阔水域 | 船速和帆角关系清晰 | 读风与调帆 |
| 逆风目标 | 目标在逆风方向 + 无礁石 | 不能直接前进 | 之字航行规划 |
| 漂移航线 | 横向洋流 + 窄航道 | 看似正确的航向会偏离 | 提前补偿 |
| 礁石风道 | 密集礁石 + 变风 | 安全路径和风向互相冲突 | 路线规划与风险判断 |
| 雾中返航 | 低能见度 + 弱风 + 时间限制 | 信息不足且行动缓慢 | 谨慎探索与优先级判断 |

5. **形成学习曲线**：

```text
单变量挑战 → 双变量组合 → 环境冲突 → 综合航行任务
```

**输出**：

- 领域因素清单
- 挑战维度表
- 挑战组合表
- 能力对应表
- 2-3 个可以进入最小可玩原型的递进挑战

**检查问题**：

- 这个挑战是否来自领域因素，而不是随便添加障碍？
- 玩家是否能读到造成挑战的因素？
- 失败后玩家是否知道下次该观察什么、调整什么？
- 挑战是否让玩家更像这个领域的学习者，而不是只像普通游戏玩家？

### Step 5：最小可玩原型

**目标**：做一个能让玩家经历“从不会到会一点”的核心循环。

可以是：

- 纸面原型
- 身体原型
- 卡牌原型
- p5.js / Scratch / GDevelop 原型
- Unity 模板原型

第一版只验证一个问题：

> 玩家是否需要学习这个领域的判断方式，才能玩得更好？

如果课程允许使用 AI-Agent（如 Codex、WorkBuddy）辅助实现，第一版建议包含 Step 4 中的 2-3 个递进挑战。这样学生可以验证同一核心循环在不同挑战条件下是否仍然成立，并初步形成学习曲线。

推荐结构：

```text
挑战 1：单变量挑战 → 挑战 2：双变量组合 → 挑战 3：综合局面
```

如果没有 AI-Agent、时间很短或学生技术基础较弱，可以先只完成挑战 1，但设计文档仍应保留挑战 2 和挑战 3。

### Step 6：AI 辅助开发

AI 可以帮助实现、整理变量、生成代码或制作素材，但学生必须保留设计判断。

记录时重点写清楚：

- AI 帮助了什么
- 学生接受、修改或拒绝了什么
- AI 是否把领域结构简化成普通小游戏
- 学生如何把设计拉回领域学习体验

### Step 7：游戏世界拓展

**目标**：在核心循环和挑战空间成立后，把领域逻辑扩展成一个可持续的游戏世界。

可以拓展：

- 更复杂的环境条件和挑战组合
- 更多工具和参数
- 新手到高手的关卡序列
- 不同风格的挑战任务
- 玩家长期成长与反思

## 5. 判断标准

本分支最重要的判断标准是：游戏是否让玩家体验到领域中的思考方式。

### 5.1 浅层转译

```text
领域题材 + 普通游戏机制
```

例子：

- 帆船皮肤的赛车游戏
- 攀岩皮肤的平台跳跃
- 摄影主题的找茬游戏

这类作品可以好玩，但研究价值较弱，因为领域知识只是包装。

### 5.2 中层转译

```text
领域流程 + 操作模拟
```

例子：

- 按步骤升帆
- 按顺序打结
- 按提示设置相机参数

这类作品有教学价值，但容易变成训练软件。

### 5.3 深层转译

```text
领域认知方式 + 技能反馈循环
```

例子：

- 帆船游戏让玩家逐渐学会读风、借力和处理不可控环境
- 攀岩游戏让玩家从蛮力转向路线阅读、重心控制和体力管理
- 摄影游戏让玩家从拍清楚转向用光线、构图和等待建立观看方式

这是本分支最希望达到的层次。

## 6. 教学产出

每个学生或小组最终应提交：

1. 领域学习采样表
2. 新手/高手差异卡
3. 技能循环图
4. 领域反馈表
5. 数据化变量表
6. 挑战维度表与挑战组合表
7. 最小可玩原型
8. 玩家试玩反馈
9. 设计师陈述

建议最终展示问题：

> 你希望玩家通过这个游戏学会“怎么看”这个领域？

## 7. 研究价值

本路径体现了本项目方法论上的一次重要扩展：它说明“来自生活”的真实经验不只包括情感事件，也包括学习一个真实领域时逐渐形成的认知方式、技能循环和反馈理解。

情感经验路径强调：

> 情感是生活与游戏之间的重要桥梁。

领域学习路径补充：

> 技能学习、认知变化和反馈理解也是生活与游戏之间的重要桥梁。

这使“来自生活的游戏设计”从单一情感路径扩展为更完整的方法体系：

```text
真实生活经验
├── 情感经验路径：生活事件 → 情感结构/情感原型 → 挑战空间设计 → 游戏机制
└── 领域学习路径：学习过程 → 认知/技能结构 → 挑战空间设计 → 游戏机制
```

## 8. 课堂检查问题

用于快速判断一个项目是否仍然贴合本分支：

1. 如果去掉领域题材，这个机制还成立吗？
2. 玩家是否真的需要像该领域学习者一样观察和判断？
3. 游戏是否呈现了新手常见误解？
4. 游戏是否提供了有意义的反馈，而不是只给分数？
5. 玩家是否能通过反复尝试形成更好的策略？
6. 原型是否让玩家体验到“开始看懂这个领域”的时刻？
