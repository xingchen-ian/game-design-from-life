# INSIDE Design Analysis Demo

> 用于夏令营第一次课  
> 方法定位：**情感路径作为解释框架，Domain Learning 作为系统分析工具**  
> 核心目标：让学生看到，一个成熟游戏如何通过行动、反馈和挑战空间，让玩家学习一种情感化的生存判断。

---

## 0. 为什么重新压缩问题

原来的版本更接近完整研究访谈，问题很全，但第一次课现场使用会偏多。学生刚玩完 `INSIDE`，最需要的是形成一种分析眼光，而不是填写一份长表。

因此，第一次课建议使用 **4 个 part，12 个核心问题**：

1. 情感经验：这个片段让玩家进入什么情感处境？
2. 玩家学习：玩家从不会到会，学会了什么判断？
3. 反馈与挑战空间：游戏如何用环境因素制造挑战？
4. 最小原型迁移：如果提取一个可做的小原型，保留什么？

教师可以口头追问更多细节，但学生纸面或投影上不需要看到所有追问。

---

## 1. 课堂使用方式

建议流程：

1. 学生试玩或观看 `INSIDE` 开场片段，约 10-15 分钟。
2. 不先讲剧情和作者意图，只让学生记录：我看见了什么，我做了什么，我什么时候失败，我失败后学会了什么。
3. 教师用下面 12 个核心问题做一次现场演示。
4. 最后连接到学生自己的项目：他们也要找到一个真实经验或领域学习过程，并把它变成可玩的观察、判断、行动、反馈和挑战空间。

推荐分析片段：

- 森林开场
- 车辆灯光
- 追捕者
- 狗
- 阴影、掩体、跳跃和逃跑

课堂提醒：

- 不要求学生模仿 `INSIDE` 的题材、美术或黑暗风格。
- 分析重点不是“这个游戏讲了什么故事”，而是“它如何让玩家在压力中学会读懂这个世界”。

---

## 2. 总框架

`INSIDE` 更适合以情感路径解释：

```text
情感处境：弱小、被追捕、被监视、必须前进
        ↓
玩家行动：跑、停、躲、跳、等待、利用掩体
        ↓
系统反馈：被发现、被追上、死亡、逃脱、进入安全区
        ↓
挑战空间：灯光、视线、狗、距离、掩体、时间窗口
        ↓
玩家体验：压迫、紧张、无助但必须判断
```

Domain Learning 在这里作为分析工具：

```text
观察 -> 判断 -> 行动 -> 反馈 -> 调整 -> 更会读这个世界
```

也就是说，`INSIDE` 不是让玩家学习“一个现实领域”，而是让玩家学习“这个世界如何运作”。这个学习过程服务于情感体验。

# Part A: 问题设计

## Part 1: 情感处境

**为什么设置这个 part**：  
先确定游戏想让玩家处在什么情感结构里。否则学生容易只分析操作、关卡或美术，而看不见这些系统设计服务于什么体验。

1. 这个片段让玩家处在什么处境中？  
   教师追问：玩家是强大还是弱小？自由还是受控？安全还是暴露？

2. 这个处境带来的核心情感是什么？  
   教师追问：恐惧、紧张、压迫、孤独、无助、好奇，哪个最强？它如何变化？

3. 游戏没有直接说出这些情感，它用哪些画面、声音、空间或规则让玩家感受到？  
   教师追问：光线、距离、沉默、死亡方式、追捕者行为分别有什么作用？

---

## Part 2: 玩家学习循环

**为什么设置这个 part**：  
这是借用 Domain Learning 的工具。我们要看玩家如何从“不会读这个世界”变成“会根据环境信号行动”。

4. 玩家一开始最容易误解什么？  
   教师追问：是不是以为只要一直向右跑、动作快一点就可以？

5. 玩家失败后开始观察什么？  
   教师追问：灯光、狗的距离、敌人的视线、掩体、跳跃距离、声音节奏。

6. 玩家形成的核心学习循环是什么？

```text
观察什么 -> 判断什么 -> 做什么 -> 得到什么反馈 -> 下次如何调整
```

---

## Part 3: 反馈与挑战空间

**为什么设置这个 part**：  
这是系统分析的核心。`INSIDE` 的挑战不是随机难题，而是由少数因素不断组合：灯光、视线、狗、距离、掩体、时间窗口。学生要学会从系统因素推导挑战。

7. 游戏给玩家的关键反馈有哪些？  
   教师追问：哪些是视觉反馈？哪些是声音反馈？哪些是死亡或失败反馈？

8. 这个片段的挑战因素有哪些？  
   教师追问：灯光范围、敌人视线、狗的速度、掩体位置、距离、跳跃时机、声音提示。

9. 这些因素如何组合成从简单到复杂的挑战？  
   教师追问：先单独出现什么？后来哪些因素叠加？叠加后玩家必须改变什么策略？

---

## Part 4: 最小原型迁移

**为什么设置这个 part**：  
分析成熟游戏不是为了复制它，而是为了提取一个可学习、可实现的小系统。这一步把分析转回学生自己的创作。

10. 如果只保留一个 30 秒核心循环，玩家能做什么？  
    教师追问：移动、等待、躲藏、冲刺、通过灯光区域。

11. 这个小原型最需要保留哪些反馈，才能保留原来的情感体验？  
    教师追问：被看见、暂时安全、追捕变近、时机错误、成功逃脱。

12. 设计 2-3 个递进挑战，难度如何变化？  
    教师追问：固定灯光 -> 移动灯光 -> 灯光 + 狗 / 追捕压力。

# Part B: 示范回答

## Part 1: 情感处境

### 1. 这个片段让玩家处在什么处境中？

玩家是一个弱小的男孩，处在一个敌意很强的世界里。他没有武器，也没有明确解释，只能不断向前逃。周围有车辆、追捕者、狗、灯光和黑暗森林。玩家感到自己随时会被发现。

这个处境的结构可以概括为：

```text
弱小身体 + 敌意环境 + 信息不足 + 必须前进
```

### 2. 核心情感是什么？

核心情感不是单纯恐怖，而是“被追捕的压迫感”和“无助中的紧张判断”。

情感轨迹大致是：

```text
不确定 -> 警觉 -> 被追赶的紧张 -> 失败后的惊吓 -> 学会观察后的短暂安全感
```

### 3. 游戏如何让玩家感受到这些情感？

它主要通过非文字方式：

| 设计元素 | 情感作用 |
| --- | --- |
| 黑暗森林和远景空间 | 让玩家感到孤立和方向不明 |
| 车辆灯光 | 制造被监视、被发现的压力 |
| 狗叫声和奔跑声 | 让追捕压力变得身体化 |
| 男孩脆弱的死亡表现 | 强化玩家的无力感 |
| 很少 UI 和文字说明 | 让玩家必须自己判断世界规则 |

---

## Part 2: 玩家学习循环

### 4. 玩家一开始最容易误解什么？

新手容易以为：

```text
这是一个向右跑的平台游戏，只要跑快一点就能逃走。
```

但很快会发现，单纯跑不够。跑得太早、太晚、太直，都会失败。

### 5. 玩家失败后开始观察什么？

失败后，玩家开始观察：

- 灯光什么时候扫过来
- 狗和自己的距离
- 敌人的方向和停顿
- 哪里有阴影或掩体
- 哪些地形可以跳、爬、钻
- 什么时候应该停，什么时候应该冲

这就是从“操作角色”转向“读取环境”。

### 6. 核心学习循环是什么？

```text
观察灯光/敌人/狗/掩体
-> 判断现在跑、停还是躲
-> 执行动作
-> 看到被发现、被追上、死亡或成功通过
-> 调整行动时机和路线
-> 更会读这个危险世界
```

这个循环和 Domain Learning 的结构相似，但它服务的不是现实技能，而是情感体验：玩家越会读世界，越能感受到这个世界的压迫和危险规则。

---

## Part 3: 反馈与挑战空间

### 7. 关键反馈有哪些？

| 反馈信号 | 来自哪里 | 告诉玩家什么 | 表现方式 |
| --- | --- | --- | --- |
| 灯光照到角色 | 探照灯/车辆 | 玩家暴露了 | 光束扫过，角色处在亮处 |
| 狗叫声变近 | 狗 | 追捕距离正在缩短 | 声音更近、更急 |
| 敌人转身或停顿 | 敌人行为 | 行动窗口变化 | 动作方向改变 |
| 角色死亡或被抓 | 失败结果 | 当前路线或时机错误 | 直接失败并重来 |
| 成功进入阴影 | 空间与光线 | 当前躲藏有效 | 敌人未发现，压力下降 |

这些反馈几乎不用分数。玩家是通过画面、声音、动作结果和失败来学习。

### 8. 挑战因素有哪些？

| 挑战因素 | 简单状态 | 困难状态 | 玩家需要学会什么 |
| --- | --- | --- | --- |
| 灯光 | 固定或慢速 | 移动扫射 | 判断暴露窗口 |
| 狗 | 距离远 | 速度快、距离近 | 控制逃跑节奏 |
| 掩体 | 明显且近 | 少、远、需要提前规划 | 观察安全路线 |
| 敌人视线 | 单一方向 | 多方向或突然变化 | 预判危险 |
| 时间窗口 | 宽 | 窄 | 精确行动 |
| 地形 | 平路 | 跳跃、攀爬、钻过 | 把操作和时机结合 |

### 9. 挑战如何从简单到复杂？

一个可能的递进是：

```text
单一危险：看到灯光，知道亮处危险
-> 双因素：灯光 + 掩体，学会等待和躲藏
-> 追捕压力：狗 + 距离，学会边跑边判断
-> 综合挑战：灯光 + 狗 + 地形 + 时间窗口，学会在压力下读环境
```

这说明 `INSIDE` 的关卡不是随机摆放危险，而是逐渐增加需要同时判断的因素。

## Part 4: 最小原型迁移

### 10. 30 秒核心循环是什么？

可以做一个“逃离探照灯”的小原型：

```text
玩家从左侧出发
-> 观察移动灯光
-> 等待安全窗口
-> 冲到下一个掩体
-> 如果暴露太久就失败
-> 成功到达右侧安全门
```

玩家只需要：

- 左右移动
- 等待
- 躲在掩体后
- 抓住时机冲刺

### 11. 必须保留哪些反馈？

必须保留：

- 灯光照到角色时的危险反馈
- 角色躲进阴影后的安全反馈
- 被发现前的短暂警告
- 失败后的快速重试
- 成功通过后的压力释放

可以省略：

- 复杂剧情
- 精细美术
- 多种敌人
- 长关卡
- 真实物理

### 12. 2-3 个递进挑战

| 原型挑战 | 因素组合 | 学习目标 |
| --- | --- | --- |
| 固定灯光 | 灯光 + 一个掩体 | 明白亮处危险，阴影安全 |
| 移动探照灯 | 移动光束 + 两个掩体 | 学会等待时机再行动 |
| 灯光与追狗 | 移动光束 + 追赶距离 | 在时间压力下判断行动窗口 |

这个原型不是复制 `INSIDE`，而是提取它的一个核心系统：

```text
被监视的情感处境
-> 观察危险信号
-> 判断行动窗口
-> 反馈中学习
-> 形成压迫感
```

## 3. 教师版补充问题

如果课堂时间充足，可以追加这些问题；如果时间紧，不建议放到学生主表里。

### 情感路径补充

1. 这个片段的情感高峰在哪里？
2. 玩家什么时候最无助？
3. 游戏有没有让玩家产生短暂掌控感？这种掌控感为什么不完全消除压迫？

### 系统分析补充

1. 哪些变量可以实现这个系统？例如 `visibility`、`dogDistance`、`lightPosition`、`detectionTimer`。
2. 哪些状态最重要？例如 `hidden / visible`、`safe / danger`、`detected / undetected`。
3. 失败后玩家能否知道自己错在哪里？

### 原型设计补充

1. 如果让 AI 帮你做这个原型，提示词必须说明哪些系统结构？
2. AI 可能会把这个原型变成什么普通小游戏？
3. 你会拒绝哪些 AI 建议？

---

## 4. 是否每个问题都必要？

不是都必要。建议分三层使用：

| 层级 | 用途 | 问题数量 | 是否给学生 |
| --- | --- | --- | --- |
| 核心演示版 | 第一次课现场分析 | 12 个 | 给学生 |
| 教师追问版 | 课堂讨论时灵活追问 | 约 9 个 | 教师掌握 |
| 完整研究版 | 后续写作、访谈、项目归档 | 可扩展到 30+ | 不适合第一次课直接使用 |

第一次课最关键的问题不是多，而是让学生记住一个分析动作：

```text
这个游戏想让玩家感受到什么？
玩家一开始不会什么？
游戏通过什么反馈让玩家学会？
这些挑战是由哪些系统因素组合出来的？
```

只要这四个问题成立，课堂目标就达到了。

---

## 5. 教师总结话术

可以这样收束这次演示：

> 我们今天不是在评价 `INSIDE` 好不好玩，也不是复述它的剧情。我们在分析：它如何让玩家进入一种情感处境，并通过观察、判断、行动、反馈和失败，让玩家学会这个世界的规则。  
> 之后你们做自己的项目，也要这样思考：先找到一个真实经验或领域学习过程，再把它转化为玩家可以观察、判断、行动、失败、调整的游戏系统。
