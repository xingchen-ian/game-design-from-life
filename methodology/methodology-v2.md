## 第一部分：核心理念

### 1.1 一句话概括

**游戏是艺术，创新源于生活——从一段有难度的生活过程中，同时读出判断如何改变、感受如何发生，抽出最小互动循环，再把它展开为游戏世界。**

### 1.2 核心命题

1. **真实经验是起点**：一段你经历过的、有阻力的过程。可以是事件、身体处境、社会情境，也可以是正在学的一项技能。差别在阻力长在哪里，不在「这是情感还是学习」。
2. **难度同时产生学习与情感**：有难度就会调整判断；学习一定伴有感受。二者是同一过程的两面。抽掉判断会变成气氛；抽掉感受会变成训练软件。
3. **最小循环是脊柱**：玩家反复做的那件事，必须同时扛住判断变化和情感轨迹。
4. **挑战空间是关键桥接**：变量表本身还不是游戏。只有把变量组合成一组彼此有关系的挑战，循环才进入游戏设计。完整游戏里，这种关系首先是变奏的、生态的、戏剧—叙事的，而不是默认的难度递进。
5. **转化是艺术**：游戏不是生活的模拟。游戏体验与现实体验之间的差异，正是游戏作为艺术形式的独特性所在。
6. **实践是根基**：方法论在真实设计实践中检验和发展，学生在实践中学习和贡献。

### 1.3 同一过程的两面（不再分路径）

| 面 | 核心问题 | 仍可使用的工具 | 合在一句里的验证 |
| --- | --- | --- | --- |
| 判断 | 一开始如何看错？后来如何看对？失败后下次看什么？ | 新手/高手差异、OJAFA 循环 | 玩过之后，他们是否开始用那种方式**看**这件事，并以那种方式**感受**它？ |
| 感受 | 什么触发？张力是什么？何时转折、高峰、余韵？ | 情感结构七步、情感原型卡片 | 同上，一句，不拆成两套标准 |

**教学取样**（不是理论分叉）：生活经验较单一时，从正在学的技能取过程；材料更丰富时，从事件、关系、制度取过程。分析格式相同。

### 1.4 艺术转化原理（理论基础）

> "如果游戏是艺术，游戏就不应当是简单的生活模拟。"

这是本方法论最深层的理论问题：**游戏体验与现实体验的根本差异是什么？**

#### 电影与游戏的参照

| | 电影 | 游戏 |
|--|------|------|
| 媒介手段 | 蒙太奇、景别、声画关系、剪辑节奏 | **交互规则、能动性、系统涌现** |
| 与现实关系 | 记录 + 剪辑 + 重构 | 模拟 + 结构化 + 互动 |
| 观众位置 | 被动的观察者 | **主动的参与者** |
| 转化本质 | 把时间和空间重新组织 | **把体验重新结构化** |

#### 游戏艺术的四种转化手段

**① 抽象化（Abstraction）**
- 现实：复杂的、充满噪音的体验
- 游戏：提取核心情感，去掉无关细节
- 例：现实"赶地铁"有无数琐事 → 游戏只保留"时间紧迫 + 关键决策"
- 设计原则：**只保留服务于情感目标的元素**

**② 结构化（Structuring）**
- 现实：模糊的、没有明确目标的体验
- 游戏：给体验一个清晰的结构（目标/挑战/反馈）
- 例：现实中"遗憾"是模糊的 → 游戏中变成"你做了一个选择，看到另一个可能性，但无法回去"
- 设计原则：**用规则赋予体验以形式**

**③ 放大（Amplification）**
- 现实：情感是微弱的、被日常稀释的
- 游戏：把情感推到极致
- 例：现实"绝处逢生"可能只是赶上公交 → 游戏中是"最后一秒启动自毁装置"
- 设计原则：**让玩家体验到日常生活中无法达到的情感强度**

**④ 安全容器（Safe Container）**
- 现实：某些体验代价太高（危险、道德困境、失败）
- 游戏：提供"可以犯错的空间"
- 例：现实中不敢辞掉不喜欢的工作 → 游戏中可以体验"裸辞后生存"
- 设计原则：**让玩家安全地体验危险的情感**

#### 关键理论支撑

- **Janet Murray**《Hamlet on the Holodeck》— 沉浸（Immersion）、能动性（Agency）、变形（Transformation）
- **Jesper Juul**《The Art of Failure》— 游戏作为"自愿克服困难"的艺术
- **Ian Bogost**《Persuasive Games》— 程序修辞（Procedural Rhetoric），游戏用规则"说理"
- **Salen & Zimmerman**《Rules of Play》— "有意义游戏"（Meaningful Play）

### Step 1：生活感受（Lived Experience）

**目标**：从一段有难度的生活过程出发，识别动作、过程、阻力，以及判断如何改变、感受如何发生。

**输入**：一段真实的生活经历（自己的、他人的、观察到的）

**过程**：

1. **描述体验**：用2-3句话描述发生了什么
2. **三维分析**：

| 维度 | 核心问题 | 示例（"赶最后一班地铁"） |
|------|---------|------------------------|
| **动作** | 你/他人做了什么？ | 奔跑、看表、挤过人群、跳上车门 |
| **过程** | 事情如何展开？时间线是什么？ | 发现快迟到→加速→遇到阻碍→最后冲刺→成功/失败 |
| **情感** | 关键时刻的感受是什么？ | 焦虑→紧张→绝望→如释重负（或愤怒） |

3. **要素补充**（Tier 2，强烈推荐）：

| 维度 | 核心问题 |
|------|---------|
| **空间** | 这个体验发生在什么空间？空间特征如何影响体验？ |
| **对象** | 涉及哪些人/物/信息？它们之间的关系是什么？ |

4. **要素可选补充**（Tier 3，可选）：

| 维度 | 核心问题 |
|------|---------|
| **规则** | 这个体验中有哪些隐含的"规则"？（社会规则、物理限制等） |
| **反馈** | 行为产生了什么后果？ |

**输出**：一张三维分析表（动作/过程/情感 + 空间/对象）

**教学提示**：
- 鼓励学生从自己经历过的、有难度的过程出发，而非虚构
- 动作/过程/阻力之外，判断变化与情感轨迹两面都要读；缺一面，后面的循环会塌
- 青少年课堂上可从正在学的技能取样——这是入口策略，不是另一条方法
- 如果某个维度分析困难，说明这段体验可能不适合作为设计起点

### Step 2：情感原型（Emotional Prototype）

**目标**：从Step 1的生活感受中提取核心情感，识别或创建情感原型。

**关键转变**：从v1的"固定原型库"转向"自下而上、逐步生长的开放库"。

**为什么不是固定库？**
- 生活中的情感是多变的、多样的，无法被预设列表完全覆盖
- 固定库容易让学生变成"选填题"思维，而非创造性思考
- 自下而上建库本身就是一种研究方法（扎根理论方法），也是学术贡献

**过程**：

1. **情感命名**：用1-3个词精确命名核心情感
2. **情感结构分析**：

| 元素 | 核心问题 |
|------|---------|
| 触发条件 | 什么引发了这种情感？ |
| 核心张力 | 这种情感中最大的矛盾是什么？ |
| 转折点 | 情感发生质变的时刻 |
| 情感高峰 | 最强烈的瞬间是什么？ |
| 余韵 | 体验结束后留下了什么？ |

3. **原型匹配或创建**：
   - 先查看已有原型库（见附录A）
   - 如果找到匹配 → 参考该原型的转化策略
   - 如果没有匹配 → **创建新原型**，记录以下信息：
     - 原型名称（中文 + 英文）
     - 生活场景描述
     - 核心情感结构
     - 初步的游戏转化思路
   - 新原型贡献回原型库，形成生长式积累

4. **情感等价检验（预检）**：
   - 问自己：如果一个人没有这段经历，他能否通过游戏理解这种情感？
   - 如果能 → 这个原型具有普遍共鸣潜力
   - 如果不能 → 考虑这个原型的文化/个体特异性

#### 情感原型分析法

情感原型库的价值不在于穷举所有情感，而在于提供一种可迁移的分析方法。原型库是分析结果，分析法才是持续生成、修正和验证原型的引擎。

一个情感原型不应只是"焦虑""愤怒""遗憾"这样的情绪标签，而应记录一种情感如何在具体生活情境中发生、展开并留下余韵。建议用以下七步分析：

| 步骤 | 核心问题 | 产出 |
|------|---------|------|
| 1. 生活情境记录 | 发生了什么？谁在什么情境中做了什么？ | 具体生活片段 |
| 2. 情感命名 | 这段体验最核心的感受是什么？ | 1-3个情感词 |
| 3. 触发条件分析 | 什么条件引发了这种感受？ | 触发因素列表 |
| 4. 张力结构分析 | 当事人想要什么？什么阻止了他？ | 欲望-阻碍结构 |
| 5. 情感轨迹分析 | 情绪如何随时间变化？何时转折、何时达到高峰？ | 情感时间线 |
| 6. 机制转译分析 | 哪些张力、变量、行动和反馈可以转成游戏系统？ | 机制线索 |
| 7. 体验验证 | 玩家是否感受到相似的情感结构？ | 试玩/访谈反馈 |

这七步可以用于分析已有原型，也可以用于创建新原型。它的关键不是把所有体验归入已有分类，而是让学生学会把模糊的生活感受拆解为可讨论、可设计、可验证的结构。

#### 情感原型研究结构

从研究角度看，情感原型库应被视为开放式的设计知识库，而不是封闭的情感分类体系。它的积累方式是循环迭代：

```
情感分析方法 → 情感原型 → 机制转译 → 原型测试 → 方法修正 → 原型库扩展
```

每完成一次设计实践，都应回到两个问题：

1. 这个案例是否产生了新的情感原型，或修正了已有原型？
2. 玩家反馈是否说明我们的情感分析方法需要调整？

因此，学术贡献不只在于"总结了多少种情感"，而在于提出并迭代一套能够持续生成情感原型的研究方法。

**输出**：情感原型卡片（匹配已有或新创建）

**学术价值**：
- 逐步建立的情感原型库本身是一个**原创学术贡献**
- 类似于：心理学中的情感分类、文学中的叙事原型、电影中的类型学
- 但聚焦于"生活情境 → 游戏机制"的转化维度，是**游戏研究领域的独特贡献**

**已有的核心原型**（v1.0，待在实践中扩展）：

| # | 名称 | 英文 | 核心情感轨迹 |
|---|------|------|-------------|
| 1 | 绝处逢生 | Against All Odds | 紧张→绝望→希望→狂喜 |
| 2 | 三顾茅庐 | Persistent Effort | 挫败→坚持→怀疑→突破→成就感 |
| 3 | 遗憾 | Regret | 选择→失去→反思→接受/成长 |
| 4 | 惊喜 | Serendipity | 好奇→探索→意外→愉悦 |

### Step 3：数据化抽象（Datalization）

**目标**：将Step 1和Step 2的分析结果转化为可以被程序表示的变量和关系。

**核心理念**：游戏系统本质上是一个"变量 + 规则 + 反馈"的系统。数据化抽象就是找出生活体验中可以被表示为程序变量的要素。

**三个核心问题**（来自30分钟训练营）：
1. 这个体验中的**某个要素**能否表示为一个数据？（一个数字、一个状态、一个标签…）
2. 什么**动作**导致这个数据发生变化？
3. 基于这个数据，能设计什么**挑战**？

**过程**：

1. **识别关键变量**：

| 变量类型 | 描述 | 示例（"赶地铁"） |
|---------|------|-----------------|
| 数值型 | int / float | 距离站台的米数、剩余秒数 |
| 状态型 | bool / enum | 是否上了车、门是否关闭 |
| 集合型 | List / Array | 手中的物品、同行的伙伴 |
| 向量型 | Vector3 | 玩家位置、障碍物位置 |

2. **定义变量关系**：
   - 哪些变量互相影响？
   - 变量变化的因果关系是什么？
   - 有没有阈值（threshold）？达到/跌破阈值会怎样？

3. **设计机制流程图（Mechanic Flowchart）**：

| 列 | 内容 | 示例 |
|----|------|------|
| Goal | 玩家要达成什么？ | 在关门前进站 |
| Challenges | 什么阻碍玩家？ | 人群拥挤、距离远、时间少 |
| Player Inputs | 玩家可以做什么？ | 移动方向、加速、绕路 |
| Variables | 关键变量 | 距离(float)、时间(float)、体力(float) |

4. **最小可玩核心（Minimum Playable Core）**：
   - 识别出最少需要哪些变量才能传达核心情感
   - 剔除一切不直接服务于情感的变量
   - 理想情况下，3-5个核心变量就够了

**输出**：
- 变量表（类型 + 范围 + 初始值）
- 机制流程图
- 最小可玩核心描述

### Step 3.75：挑战空间设计（Challenge Space Design）

**目标**：把 Step 3 的变量和关系进一步推导为可玩的挑战、关卡、任务和局面，使游戏不只是一个能运行的系统，而是一个能持续产生压力、策略、学习和成就感的游戏。

**核心理念**：挑战不是灵感列表，而是系统变量的特定组合。一个挑战应同时说明：

1. 哪些变量被改变？
2. 这些变量如何组合成局面？
3. 玩家必须学习或使用哪种能力才能应对？
4. 这个挑战是否强化原始生活体验或核心情感？

**挑战设计公式**：

```text
挑战 = 系统变量的特定组合 + 对玩家能力的特定要求
```

**过程**：

1. **列出挑战维度**：从变量表中找出真正会改变玩家决策、反馈和情感压力的因素。

| 筛选问题 | 判断标准 |
| --- | --- |
| 是否改变玩家决策？ | 如果变量变化不影响玩家操作，它只是背景。 |
| 是否能被玩家感知？ | 玩家必须能通过画面、声音、手感、仪表或状态读到它。 |
| 是否改变反馈？ | 同一行动在不同条件下产生不同结果，才有挑战价值。 |
| 是否能形成难度层级？ | 变量应能从简单到复杂逐步变化。 |
| 是否对应原体验能力？ | 它应考验原生活/领域中的真实判断，而不是无关反应。 |

2. **建立挑战维度表**：

| 系统因素 | 低强度 | 中强度 | 高强度 | 主要考验 |
| --- | --- | --- | --- | --- |
| 时间压力 | 充足 | 紧张 | 极限倒计时 | 优先级判断 |
| 资源数量 | 充足 | 需要取舍 | 严重不足 | 风险与收益判断 |
| 信息完整度 | 清晰 | 部分隐藏 | 高度不确定 | 推测与试探 |
| 他人干扰 | 无 | 偶发 | 持续干扰 | 计划调整 |

3. **设计挑战组合表**：把 2-4 个维度组合成不同类型的挑战。

| 挑战名称 | 变量组合 | 玩家压力 | 训练/考验的能力 | 情感目标 |
| --- | --- | --- | --- | --- |
| 最后一刻 | 时间少 + 距离远 + 体力低 | 紧迫 | 取舍与路线判断 | 绝处逢生 |
| 不公平队列 | 他人插队 + 规则模糊 + 社会压力 | 愤怒/犹豫 | 规则利用与道德判断 | 公平焦虑 |

4. **编排挑战之间的关系**（不要默认画成难度梯子）：

挑战空间是一个**集合**，不是一条斜线。组合出若干合法变奏之后，要问的是它们如何相关，而不是哪个更难。

| 关系 | 含义 | 何时用 |
| --- | --- | --- |
| **变奏** | 同一循环的不同读法 | 始终；这是空间本身 |
| **生态 / 场所** | 变奏长成并存的地方 | 进入世界拓展时 |
| **戏剧—叙事** | 对比、因果、反复、歇息、揭示 | 完整游戏的默认编排 |
| **试玩递进** | 少变量 → 多变量的阅读顺序 | 仅用于原型验证，不是世界结构 |

```text
挑战空间 = 合法变奏的集合（无强制顺序）
完整游戏中的编排 = 场所之间的戏剧—叙事关系
课堂原型的阅读顺序 = 可选的由简入繁（检验循环，不规定世界）
```

**输出**：
- 挑战维度表
- 挑战组合表
- 能力/情感对应表
- 3-5 个可用于原型测试的挑战场景

**检查问题**：
- 这个挑战是否来自系统变量，而不是临时剧情点？
- 玩家是否能读到造成挑战的因素？
- 玩家失败后是否知道下一次可以如何调整？
- 这个挑战是否会让玩家更接近目标情感，而不是偏离成普通玩法？
- 两个挑战并置时，能否说出它们是对比、因果、反复还是歇息——而不只是「这个更难」？

### Step 4：Unity 系统搭建

**目标**：将Step 3的数据化抽象和 Step 3.75 的挑战组合在Unity/C#中实现，创建可玩的游戏原型。

**前提**：学生需要掌握的 Unity / C# 基础
- C# 基础类型：bool, int, float, string
- 集合类型：List, Array
- Unity 基础：GameObject, Transform, Vector3, MonoBehaviour
- 基本流程：Update(), 碰撞检测, 输入处理

**过程**：

1. **从变量到代码**：将Step 3的变量表直接映射为C#字段

```
// Step 3 的变量表          →    C# 代码
// 距离(float, 0-100)      →    public float distance;
// 时间(float, 60-0)       →    public float timeLeft;
// 体力(float, 100-0)      →    public float stamina;
// 是否上车(bool)           →    public bool boarded;
```

2. **从流程图到逻辑**：将机制流程图中的Challenges和Player Inputs转化为条件判断和输入处理

```
// 玩家输入 → 变量变化
if (Input.GetKey(KeyCode.W)) { stamina -= speed * Time.deltaTime; }
// 挑战逻辑
if (timeLeft <= 0 && !boarded) { GameOver(); }
```

3. **从反馈到表现**：用Unity的视觉/音频反馈强化情感

```
// 情感强化：时间紧迫时的视觉反馈
if (timeLeft < 10f) { timerText.color = Color.red; }
```

4. **快速迭代**：
   - 先做最简版本（只有核心变量和基本交互）
   - 玩一遍 → 感受情感是否到位
   - 从 Step 3.75 中选一个挑战组合加入 → 再玩 → 再感受
   - 直到核心情感被传达

**输出**：可在Unity中运行的游戏原型

**教学注意**：
- 避免学生在技术实现上花太多时间，核心是验证情感
- 鼓励使用Unity的原型工具（如ProBuilder）快速搭建
- 代码不需要优雅，只需要能运行

### Step 5：AI 辅助开发

**目标**：利用AI Agent（如WorkBuddy）辅助Step 3和Step 4的实现，让学生专注于设计决策而非技术细节。

**Prompt 与 Skill 的差异**：

| | Prompt（自由提示词） | Skill（封装工作流） |
|--|---------------------|-------------------|
| 本质 | 学生用自然语言描述需求，AI自由生成 | 将一类常见需求封装为标准化流程 |
| 灵活性 | 高，适应任意需求 | 低，覆盖有限场景 |
| 稳定性 | 低，结果依赖措辞 | 高，封装了最佳实践 |
| 学习门槛 | 低 | 中 |
| 创造性 | 高 | 低 |
| 可复用性 | 低 | 高 |
| 适用阶段 | 探索期、创意发散 | 规范期、标准功能 |

**分阶段使用策略**：

```
教学阶段1（探索期）：以Prompt为主
→ 学生自由探索，理解AI能做什么
→ 学习如何写好Prompt（描述设计意图 + 具体需求）

教学阶段2（规范期）：从Prompt中提炼Skill
→ 把反复出现的Pattern封装成Skill
→ 学生参与Skill的编写过程（理解"好做法"是什么）

教学阶段3（创造期）：Skill + Prompt并用
→ 标准功能用Skill（快速、稳定）
→ 创新部分用Prompt（灵活、探索）
```

**学生Prompt模板**（非固定模板，供参考）：

```
我在做一个关于【情感原型名称】的游戏。
核心体验是：【用一句话描述核心体验】。

目前的变量设计：
- 【变量1】：类型，范围
- 【变量2】：类型，范围

目前的机制设计：
- 玩家可以【动作】
- 挑战是【障碍描述】

请帮我：
【具体请求：如"写一个C#脚本实现这个机制" / "优化这个变量的平衡" / "设计一个反馈效果"】
```

**教学目标**：
- 学生不是"让AI做所有事"，而是"用AI加速实现，保留设计决策权"
- 学生需要能读懂AI生成的代码，理解为什么这样写
- 学生需要能判断AI的输出是否符合设计意图，必要时修正

### Step 6：游戏世界拓展

**目标**：在已建好的核心机制上，拓展为一个有深度、有厚度的游戏世界。

**核心理念**：不是给机制"套一个皮肤"，而是基于 Step 3.75 的挑战空间，让游戏世界不断生成新的局面、任务、关卡和玩家成长路径。

**完整路径**：冷凝（经验→循环）与展开（循环→世界）的合成总图，见 `methodology/from-life-to-complete-game.md`。翻转句：不要先发明有趣的世界再找玩法；要先让核心循环的变奏要求一个地方，再让这个地方要求一段历史。叙事空间按空间×时间上的事件状态响应玩家，而不是按预写序列播放。

**四拍拓展法**：

**1. 机制变体（Mechanic Variants）**
- 同一个核心循环，不同参数/条件 → 同一模式上的合法变奏
- 例："绝处逢生"机制 → 时间紧迫版 / 资源匮乏版 / 信息不全版
- 问题：同一循环有多少种挑战变量？哪些组合会产生新的判断，而不是新的玩法？

**2. 场所物化（Place）**
- 每组挑战必须对应一个地方：场所 = 物化后的挑战
- 例：横向强流 + 窄航道 → 海峡，而不是「第 3 关」
- 问题：抽掉这个地方，这组挑战还站得住吗？站不住，说明地方是被挑战要求出来的。

**3. 世界规则（World Rules）**
- 这些地方共享一套"物理/文化定律"，让虚构提示规则（Juul）
- 叙事空间 = **空间 × 时间** 的动态系统：场所并存，世界时间推移，事件以状态响应玩家，而不是播放预写的静态事件
- 例：不是"倒计时"这个机制，而是"这个世界里，某些决定必须在天黑前做出"；涨潮改写海峡，失事状态改写湾里的救援船
- 痕迹先于任务：沉船、错误航标是世界；救援是痕迹的可玩化（事件状态的可运行形式）

**4. 审美契约（Aesthetic Contract）**
- 一种语气把多样性收成同一个世界；玩家行为被世界记住（写入事件状态）
- 例：同一套驾船循环，*Dredge* 的民俗恐怖与《风之杖》的冒险卡通生成方向相同、世界内容全换
- 问题：这些场所如果是同一个人的记忆，会是什么感觉？选一个，删掉不合拍的内容。

**课堂工具**：场所推论五问——物化 / 痕迹 / 谁 / 语气 / 时空与状态。详见总图第 5 节。

**状态**：已从方向性初稿收成四拍；与总图 `from-life-to-complete-game.md` 对齐。

## 第五部分：学术贡献定位

### 5.1 与现有文献的对话

| 研究领域 | 代表文献 | 本方法论的回应 |
|---------|---------|---------------|
| 游戏设计模式 | Björk & Holopainen (2005) | 他们的模式是机制层面的，不涉及情感与生活的关系 |
| MDA框架 | Hunicke et al. (2004) | MDA是机制→体验的**逆向分析**路径，本方法是体验→机制的**正向设计**路径 |
| 情感设计框架 | Iosup et al. (2023) | 他们指出"情感体验依赖情境，不存在固定等价映射"——我们的回应：等价不意味着固定映射，而是通过原型和结构化设计在概率上最大化共鸣 |
| 情感共鸣机制 | Ekanayake et al. (2024) | 他们强调"为玩家留白"——本方法论与之高度契合，原型的"安全容器"设计就是为玩家留出代入空间 |
| 自传体游戏 | Anthropy (2012), Green (2016) | 他们展示了"生活→游戏"的可能性，但作为**艺术特例**；本方法论将其**系统化、可教授化** |
| 反思性游戏 | Harrer & Hammer (2024, CHI) | 他们的框架解释了游戏如何引发反思；本方法论提供了**如何设计反思性游戏**的具体路径 |
| 游戏设计模式库 | ACM CHI 2025 - 116 mechanics-emotion pairs | 这是一个**数据驱动的映射数据库**，与本方法的区别在于：我们从生活出发，他们从机制出发 |
| 领域学习与技能习得 | Learning sciences / situated learning | 这些研究解释人如何进入一个领域、形成判断和读取反馈；本方法论将其转化为可玩的挑战空间和游戏系统 |

### 5.2 本方法论的原创学术贡献

1. **"真实生活经验→游戏系统"的正向设计框架**：填补现有文献中"从体验到机制"的方法论空白。经验起点是一段有难度的生活过程；判断变化与情感轨迹作为同一过程的两面被读出，而不是两条并列路径。

2. **情感原型的系统化**：
   - 不是预设固定列表，而是自下而上逐步建立的开放库
   - 这个"建库方法"本身具有方法论价值（扎根理论在游戏设计中的应用）
   - 积累的原型库将成为游戏设计领域的独特资源

3. **判断变化作为经验结构的一面**（原「领域学习路径」收束于此）：
   - 新手/高手差异、技能循环、领域反馈是读「如何开始看懂」的工具
   - 避免把真实过程做成知识问答或题材换皮
   - 教学上可作为青少年课堂的取样策略，理论上不再单列路径

4. **挑战空间设计**：
   - 明确提出挑战不是灵感列表，而是系统变量的组合
   - 把数据化抽象进一步推进为关卡、任务和学习曲线
   - 连接系统搭建与游戏世界拓展

5. **艺术转化原理**：
   - 明确提出游戏不是生活模拟，而是艺术转化
   - 四种转化手段（抽象化、结构化、放大、安全容器）提供了可操作的设计原则
   - 连接了游戏研究与美学理论

6. **AI辅助设计的教学框架**：
   - Prompt + Skill 分阶段使用策略
   - 学生保持设计决策权，AI加速技术实现
   - 这是一个新兴但重要的研究方向

| 是/否状态 | bool | `public bool isAlive;` |
| 分类/类型 | enum | `public enum State { Idle, Run, Jump }` |
| 集合/列表 | List<T> | `public List<Item> inventory;` |
| 文本/信息 | string | `public string playerName;` |

### 附录C：学术先例对照表

|------|---------|---------------|
