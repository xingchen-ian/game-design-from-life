Process

从生活过程到可迭代的游戏

先把一段需要人判断的生活过程收成系统图。图可以很早出现。人可以直接改，也可以让 AI 一起改。点 Confirm，按当前这张图生成第一版游戏。

阶段 1 按 2026-11-10 的设计说明来写。阶段 2 和阶段 3 是草案。做到哪一步，看 开发进度。

        Stage 1

        过程怎么变成图

        这一段是已经写清的部分。帆船只用来把节点对上，案例正文不在这里。

        从难的过程开始

        不是随便切一块生活。要的是一段需要人判断、人回应的过程。帆船是一个例子：新手以为「我要控制船」，要学的是读风，再调帆、转向。风向自己会变，人必须看、必须动手。完整写法在 领域学习 和 帆船对比。

        来源先记在图旁边，不另造一种节点。这里的来源是：学帆船时要读风再动手。

        图是合同，文字是读法

        阶段摘要、GDD、Build Brief 都从图来。图改了，文字才跟着改。图上的空位，文档里也标成「尚未决定」。指不回某个节点或某条边的句子，不进文档。Build Brief 直接从图出，不再从 GDD 转写一层。

        Q1 起就出图

        每确认一题，只更新这一题对应的节点或边。不用等 21 题齐了再画。Q1 到 Q4 之后，必须已经有一张起步图，空节点还在上面。

        • Q1、Q2：来源，以及候选对象。步骤先不必全部变成节点。
        • Q3：空的 intent 上先写候选体验。
        • Q4：候选 mechanic，也就是人必须介入的动词。
        • rule、variable、challenge、feedback、结束条件：全部显式留空。
        • 边先按起步图连上。这表示这类关系必须存在，不是说已经设计完。

        起步图

        和已冻结的预置一致：8 个节点，4 条边。节点可以空着。

        这时四句话只说到一半

        验收只看图，不看文档。要能说出这四句：

        1. 玩家反复做什么
        2. 世界如何回应
        3. 什么状态在变
        4. 一局何时结束

        只答了前四题，用上面这张帆船图来对：第 1 句有候选动词「调帆、转向」；第 3 句还只有线索，两个 variable 是空的；第 2 句和第 4 句说不清。空位继续留着。这时不检查能不能出 demo。

        21 题都留着，先走核心

        必答路径大约十题，为的是能把图撑起来。非核心题负责填空位、收紧取舍，不负责能不能开始出图。空位被点到，或检查标出缺了什么，再引出对应的非核心题。不要在起步时把它们排进强制队列。

        先答

        • Q1设计起点
        • Q2过程地图
        • Q3突出时刻
        • Q4主动应对
        • Q6目标体验
        • Q9玩家身份
        • Q10主要目标
        • Q11核心挑战
        • Q13核心动作
        • Q16状态资源
        • Q17行动后果
        • Q21结束结果

        后补

        • Q5核心素材
        • Q7抽象程度
        • Q8主题信息
        • Q12玩家动作
        • Q14所需技能
        • Q15变化来源
        • Q18前后依赖
        • Q19玩家反馈
        • Q20游戏进程
        • 只答 Q1–Q4：带空位的起步图。有来源、候选 intent、候选 mechanic。
        • 再答 Q6、Q9–Q11、Q13：intent 写明确；出现 entity 和第一枚 challenge；mechanic 收成 1 到 3 个核心动词。
        • 再答 Q16、Q17、Q21：补上要记住的状态、世界规则、结束条件。接近最低可玩，feedback 和第二枚挑战仍可能空着。
        • 非核心题随后补：反馈、前后依赖、后面的挑战、抽象程度和主题。

        最低可玩的底线是另一件事：至少 1 个 intent、1 个 mechanic、1 个 variable、1 条 rule、1 个 challenge，关键边连上。entity 和 feedback 可以先空着，但必须看得见。Confirm 不等到这条线。

        Blueprint vocabulary

        只用这 7 种节点、4 种边

        词汇已经冻结。这一页不另造类型。

        intent

        目标体验，或领域学习里的判断转变。

        mechanic

        玩家动词。人做了什么。

        rule

        世界如何回应，包括结束条件。

        entity

        世界上的对象。

        variable

        可改、可测的状态。

        challenge

        一次可运行的情境：改哪些变量，成功是什么。

        feedback

        人如何感知规则在工作。

        serves

        这个设计选择服务于该意图。

        feeds

        状态或对象参与该行为，读或写。

        challenges

        这个挑战改写或激活这些部分。

        signals

        这个行为或状态产生能感知的信号。

        玩家动词不是世界规则

        mechanic

        调帆、转向。这是人做的动词。Q12、Q13 写这个。

        rule

        迎风过陡会失速。这是世界怎么回应。Q16、Q17 写这个。写在同一段文档里，这个区分会消失。

        Later

        理论、题表、阅读

        用来支撑上面的流水线，不代替流水线。

        四层已经够用的理论

        体验只能间接达到：MDA

        Hunicke, LeBlanc 与 Zubek（2004）。体验（Aesthetics）不能直接做出来，要经过机制（Mechanics），在运行里变成动态（Dynamics）。Q6 写目标体验；Q12 到 Q15 是玩家反复造成的动态；Q16 到 Q19 才是机制。问答若只收成文章，容易停在「描述了体验」，还没有能运行的机制。

        游戏是形式系统

        Salen 与 Zimmerman，《Rules of Play》。一个形式系统至少要说清对象、属性、内部关系、所处情境。Q9 到 Q11 给情境和目标，Q16 给对象和属性，Q17、Q18 给内部关系。缺关系时，文章仍可以写得很完整，图会断。

        Juul 对「规则系统 + 可协商结果」的说明，用来撑 Q21：结束条件必须连回玩家一直在做的事，不能另写一套结局散文。

        存量、流量、反馈

        课上和实现里只用 Meadows 这一支的三个词。存量是系统必须记住什么（Q16）。流量是核心行动如何改变存量（Q17）。反馈是先前行动如何改变后面的选项，以及人如何看见自己做得怎样（Q18、Q19）。Q20 是这些反馈在时间里怎么积累，不是另起一条「越来越难」的轨道。

        P-Scaffold

        结构是一张可以从任意节点进入的提示地图，不是强制向导。首要的事是让缺了的结构看得见。所以不必 21 题全答完才出图。先答核心题，图上先出现带空位的结构；非核心题等空位出现再补。

        21 题各自写入图的哪里

        核心题把最低可玩结构撑起来。非核心题填空位，不负责开门。

        题短名路径写入系统图
        Q1设计起点核心来源标签：哪段生活。不是新的节点类型。
        Q2过程地图核心候选对象和步骤。先不必全部变成节点。
        Q3突出时刻核心空的 intent 上先写候选体验。
        Q4主动应对核心候选 mechanic。
        Q5核心素材后补收紧 intent：保留哪条线索。
        Q6目标体验核心主 intent。两三个具体词。
        Q7抽象程度后补intent 上的约束：保过程、保感觉，还是换皮。
        Q8主题信息后补可选注释。不能代替 mechanic 或 rule。
        Q9玩家身份核心entity（玩家 / 环境）。
        Q10主要目标核心challenge 的成功条件，或结束 rule 的线索。
        Q11核心挑战核心第一枚 challenge。
        Q12玩家动作后补候选 mechanic，供 Q13 筛选。
        Q13核心动作核心1 到 3 枚 mechanic，serves 到 intent。
        Q14所需技能后补写入 intent 的判断转变，或 mechanic 的说明。
        Q15变化来源后补哪些 variable 会在重复里改变。
        Q16状态资源核心variable / entity，feeds 到 rule 或 mechanic。
        Q17行动后果核心每个核心动作：行动、即时响应、后续后果。这是 rule。
        Q18前后依赖后补早先行动如何改后面的选项和风险。
        Q19玩家反馈后补feedback 节点，signals 边。
        Q20游戏进程后补第 2、第 3 枚 challenge。要改的是变量或规则。
        Q21结束结果核心终止用的 rule，和 Q10、Q13 对得上。
