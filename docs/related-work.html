Working note

相关研究：从系统出发设计游戏

这是过程工具和「来自生活」方法的工作笔记，不是已发表的论文。从系统模型生成可玩的游戏，不是新的主张。

先建立一个可执行的系统模型，再通过改这个系统来改游戏。这一想法并不新。过程工具和已有工具最接近的，是同一类循环：改系统描述，再生成可玩的游戏。和它们分开的，主要是入口。不是一上来画概念图或经济图，而是先被问题引导，从生活经验进入系统，并作为课堂实践来教。

这一页不在顶栏里。过程怎么走，看 过程。工具在 process-app.html。

Closest loop

改系统描述，再生成可玩的游戏

已经有一条研究，把游戏系统的可执行模型当作主要的设计对象，把可玩的游戏当作从这份模型生成或投影出来的东西。在这条线上，改系统，就是在改游戏。

最接近的循环是：先写下系统，或写下设计意图，生成一个可玩的游戏；再改这份说明，再生成一次。

Game-O-Matic

Treanor、Blackford、Mateas、Bogost · PCG 2012

作者画一张概念图，名词用动词连起来，然后生成一个简单的街机式游戏，用来表示这些关系。他们也把这个工具当作一种想法：把事件想成系统，而不是想成故事。

https://doi.org/10.1145/2538528.2538537

Gemini

Summerville、Martens、Samuel、Osborn、Wardrip-Fruin、Mateas · AIIDE 2018

从逻辑化的设计意图生成游戏，并检查得到的机制是否和这些意图的 proceduralist 读法一致。

https://doi.org/10.1609/aiide.v14i1.13013

Germinate

Kreminski、Dickinson、Osborn、Summerville、Mateas、Wardrip-Fruin · AIIDE 2020 · 第 102–108 页

在 Gemini 上加了一层图形界面。作者用卡片写下实体、资源、关系和触发，得到一批可玩的游戏，再改这些卡片来迭代。

https://doi.org/10.1609/aiide.v16i1.7417

过程工具和它们共享这一循环：改一份系统层面的描述，再生成可玩的游戏。
Economy diagram

迭代内部经济的图

第二条线拿来迭代的，是游戏内部经济的图。

Machinations

Dormans 2009；博士论文 Engineering Emergence，阿姆斯特丹大学，2012；Adams 与 Dormans，Game Mechanics: Advanced Game Design，2012

设计者用它写下资源如何产生、如何流动、如何转换，把图当作模拟来跑，再改。经典形式，以及后来的商业工具 machinations.io，迭代的是一套可以模拟的经济，通常不是从这张图生成一个能在空间里玩的游戏。

2009 年那篇，他自己引用的题目是 “Machinations: Elemental Feedback Patterns for Game Design”，收在 Saur 与 Loper 编的 GAME-ON-NA 2009: 5th International North American Conference on Intelligent Games and Simulation，第 33–40 页。会议录目录印的是 “Structure”，不是 “Patterns”。这里用他自己的题目。

Vie / Live Game Design

van Rozen · FDG 2025 · 第 1–12 页

图和正在运行的 2D 原型放在一起。加上一个 pool，可以生成一个精灵和一条标签；把一个节点做成可交互，可以生成一个按钮；机制一改，已经在玩的游戏跟着更新。

从界面看，这接近一边改系统，一边看到可玩的游戏。

https://doi.org/10.1145/3723498.3723726

Earlier claim

Nelson 与 Mateas 的主张

这些工具底下，有 Nelson 与 Mateas 更早的主张。一种有用的游戏设计表示，应该可以展开细化，可以通过推理来批评，并且可以作为可玩的图形游戏来执行。游戏是同一个形式系统的投影，不是另外写成的一件作品。

Towards Automated Game Design，AI*IA 2007。Recombinable Game Mechanics for Automated Design Support，AIIDE 2008。

https://doi.org/10.1609/aiide.v4i1.18677（2008）

Adjacent

容易混在一起，但不是同一件事

把游戏说成系统，以及系统式游戏设计，通常是在引擎里做会涌现的系统。那里没有一份单独的系统模型，再从它生成游戏。

ANGELINA（Cook、Colton 与 Gow，The ANGELINA Videogame Design System—Part I，IEEE TCIAIG 2016）是程序主要负责发明一个完整的游戏，而不是去支持一个人迭代一张系统图。

https://doi.org/10.1109/TCIAIG.2016.2520256

混合主动的关卡设计工具，迭代的是空间和布局，不是整个系统。

Entry

从生活经验进入系统

过程工具站在这条从系统出发的线上。分开的是入口，这个差别是教学上的。学生和设计者不是从画概念图开始，也不是从画经济图开始。他们先被问题引导，从生活情境里问出来源、经验和动词。这些回答变成一张系统图，图可以再改。第一版可玩的游戏，按当前这张图生成。

系统仍是主要的迭代对象。系统变了，游戏跟着变。

从系统模型生成游戏，不是新的主张。这里的贡献，是一条可教的路径：从日常生活进入这个模型，并且已经作为课堂实践在用。

Paper draft

English related work (draft)

论文用的英文相关工作草稿。措辞按原稿保留。

A line of research already treats an executable model of a game’s system as the primary design object, and treats a playable game as something generated or projected from that model. In this line, iterating the system is how the game is iterated.

The closest interaction loop is to specify a system or a design intent, generate a playable game, then revise the specification and generate again. Game-O-Matic lets authors draw a concept map of nouns linked by verbs and then generate a simple arcade-style game intended to represent those relations [Treanor et al. 2012]. The authors also present the tool as a way of thinking about events as systems rather than as stories. Gemini generates games from logical design intents and checks that the resulting mechanics are consistent with a proceduralist reading of those intents [Summerville et al. 2018]. Germinate places a graphical interface on Gemini: authors specify entities, resources, relationships, and triggers as cards, receive a batch of playable games, and revise the cards to iterate [Kreminski et al. 2020]. We share this loop of editing a system-level description and regenerating a playable game.

A second line takes a diagram of the game’s internal economy as the object to iterate. Dormans’s Machinations notation, later developed in his dissertation and in a textbook with Adams, lets designers model how resources are produced, flow, and convert, then run the diagram as a simulation and revise it [Dormans 2009; Dormans 2012; Adams and Dormans 2012]. In that classic form, and in the later commercial tool, what is iterated is a simulable economy, not usually a spatially playable game generated from the diagram. Van Rozen’s Vie brings the diagram and a running 2D prototype together: adding a pool can create a sprite and a label, making a node interactive can create a button, and changes to the mechanics update the game that is already being played [van Rozen 2025]. In its interface, this is close to editing a system on one side and seeing a playable game on the other.

Underneath these tools is an early theoretical claim by Nelson and Mateas: a useful representation of a game design should be elaborable, open to critique through inference, and executable as a playable graphical game. The game is a projection of the same formal system, not a separately authored artifact [Nelson and Mateas 2007; 2008]. Adjacent work is easy to confuse with this line but is not the same. Accounts of games as systems, and of systemic game design, usually describe building emergent systems inside an engine, without a separate system model from which a game is generated. Automated game design systems such as ANGELINA take primary responsibility for inventing a complete game, rather than supporting a human designer who iterates a system diagram [Cook et al. 2016]. Mixed-initiative tools for level design iterate spaces and layouts rather than the overall system.

Our process tool sits on this system-first line, but the entry point is different, and that difference is pedagogical. Students and designers do not begin by drawing a concept map or an economy diagram. They are guided through questions that elicit sources, experiences, and verbs from lived situations; those answers become a system diagram, which can then be edited; and a first playable version is generated from the current diagram. The system remains the primary object of iteration; the game changes as the system changes. We do not claim that generating a game from a system model is new. What we contribute is a teachable path into that model from everyday life, already used as classroom practice.
