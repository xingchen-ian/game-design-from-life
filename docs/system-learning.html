M0 第一讲：系统与状态M0 Lesson 1 · Systems and States

① 为什么系统思维是地基1) Why systems thinking is the foundation

方法论后半段（Step 3 → 3.5 → 3.75 → 4 → 5 → 6）全部是系统工作。系统思维提供三种能力：看穿结构（游戏不是点子，而是元素之间的关系网络）；与 AI 对话的前提（系统描述 = 用系统语言写规格）；以及「系统描述 vs Prompt」论题的底座。

The second half of the methodology (Step 3 → 3.5 → 3.75 → 4 → 5 → 6) is entirely systems work. Systems thinking provides: seeing structure (a game is a network of relationships, not an idea), the prerequisite for talking to AI (a system description is a spec written in systems language), and the foundation for the "System Description vs Prompt" thesis.

② 什么是系统（Meadows 定义）2) What is a system (Meadows)

系统 = 元素 + 相互连接 + 功能/目的，三者缺一不可；系统存在于边界之内，受环境影响。关键认知：是「关系」产生行为——同样的元素，连接方式不同，系统行为完全不同。

A system = elements + interconnections + function/purpose, all three required; it exists within a boundary and is affected by its environment. Key insight: relationships produce behavior — the same elements, connected differently, behave completely differently.

对方法论的意义：Step 1 生活感受的三维分析（动作/过程/情感）在收集元素；Step 2 情感结构分析在定义系统的目的；Step 3 数据化抽象把元素变成变量、关系变成规则。系统思维让你在 Step 1 就带着「结构」的眼光观察生活。

For the methodology: Step 1's three-dimensional analysis (action/process/emotion) collects elements; Step 2's emotional structure analysis defines the system's purpose; Step 3 Datalization turns elements into variables and relationships into rules.

③ 状态与状态空间3) State and state space

状态（State）= 系统在某一时刻所有变量的取值快照。状态空间（State Space）= 所有可能状态的集合。排队游戏在时刻 t 与 t+1 的两个快照，中间由事件/输入触发状态转移：

position(1–20) × waitTime(连续) × patience(0–1) × fairness(0–1) × ruleBreaking(bool) × 行动选项。数值上巨大，但规则剪枝 → 只有部分状态可达。设计不是穷举，而是用规则划定「可达空间」。

position(1–20) × waitTime(continuous) × patience(0–1) × fairness(0–1) × ruleBreaking(bool) × actions. Numerically huge, but rules prune it → only some states are reachable. Design is not enumeration; it is delimiting the reachable space with rules.

情感 = 状态轨迹：焦虑（patience↓ + waitTime↑）→ 转折（插队）→ 如释重负（到达窗口）。

Emotion = state trajectory: anxiety (patience↓ + waitTime↑) → turning point (line-jump) → relief (reaching the window).

④ 带走工具：系统看图纸4) Takeaway tool: the Systems Blueprint

分析任何系统（生活体验、现有游戏、学生作品）时，过一遍这张检查表——它把第一讲的所有概念变成可操作的问题：

When analyzing any system — a lived experience, an existing game, a student project — run through this checklist. It turns every concept from Lesson 1 into actionable questions:

□ 边界：这个系统在哪里结束？环境输入什么？
□ 元素：有哪些实体？（人/物/信息/资源）——对应 Step 1 对象维度
□ 关系：谁影响谁？箭头怎么画？（方向 + 强度）
□ 目的：系统在「追求」什么？（对应情感目标/领域目标）
□ 状态变量：哪些变量描述系统状态？类型？值域？（对应 Step 3 变量表）
□ 状态空间：变量组合会涌现出什么局面？（对应 Step 3.5 数据结构图）
□ 公开/隐藏：玩家能看到哪些？需要推断哪些？（信息设计）
□ 规则：什么事件/输入触发状态转移？（对应 Step 4 实现）□ Boundary: where does this system end? What enters from the environment?
□ Elements: what entities exist? (people/objects/info/resources) — Step 1 objects
□ Relationships: who affects whom? Draw arrows (direction + strength)
□ Purpose: what is the system "pursuing"? — emotional/domain goals
□ State variables: what describes system state? type? range? — Step 3 table
□ State space: what situations do variable combinations yield? — Step 3.5 graph
□ Public/hidden: what can players see vs. infer? — information design
□ Rules: what events/inputs trigger transitions? — Step 4 implementation

练习建议：用这张图纸重新分析 The Darkroom（摄影曝光 → 光迹机制）。它已是最强的 RtD 案例，用系统语言重述一遍，你会得到一段可直接进论文的「系统描述」草稿——提前练了 M5 的手感。

Suggested exercise: Re-analyze The Darkroom (photographic exposure → light-trail mechanics) with this blueprint. It is already your strongest RtD case; restating it in systems language yields a "system description" draft ready for the paper — early practice for M5.
