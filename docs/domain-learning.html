Domain Learning to Game System

从领域学习到游戏系统

把一个真实领域的学习过程，转译成玩家可以进入、试错、理解和掌握的游戏世界。

Pathway Method

不是知识问答，也不是领域换皮

这条路径关注的是学生如何学习一个真实领域，并把“新手逐渐看懂领域”的过程变成游戏机制。帆船、攀岩、摄影、急救、咖啡、城市骑行都可以成为起点，但最终要落在可玩的判断、挑战、反馈和成长上。

核心问题

玩家是否开始像这个领域中的学习者一样观察、判断、行动和修正？

情感经验路径

B

让玩家体验进入一个领域的思考方式
Class Flow

四次课建议节奏

每次课都产出可展示材料，避免最后只剩一个赶工原型。

01

选择领域

记录自己了解或正在学习的领域，找出新手一开始看不见什么。

产出：领域学习采样表
02

拆解技能

比较新手和高手判断，画出观察、判断、行动、反馈、调整的技能循环。

产出：新手/高手差异卡
03

制作原型

把领域对象、玩家行动、反馈信号和资源状态做成最小可玩循环，并实现 2～3 个递进挑战。

产出：挑战维度表和挑战阶梯原型
04

展演验证

让同学试玩，观察他们是否开始使用领域中的判断方式。

产出：展示海报和设计师陈述
Thinking Shift

新手和高手看到的是不同世界

帆船

新手以为

我要控制船。

高手知道

我要读取风，并调整船与风的关系。

机制方向：风向不可控，玩家通过调帆和转向借力。

攀岩

新手以为

我要用手把自己拉上去。

高手知道

我要读路线、用脚、保存体力、控制重心。

机制方向：盲目移动消耗体力，观察路线带来更优解。

摄影

新手以为

我要把画面拍清楚。

高手知道

我要组织光线、构图、等待和观看顺序。

机制方向：玩家调整参数和位置，让主体关系变清晰。

咖啡萃取

新手以为

照配方操作就会好喝。

高手知道

我要根据研磨、流速、时间和味道反馈调整。

机制方向：参数之间互相牵制，反馈不是单一分数。

Challenge Space

挑战不是灵感，而是变量组合

系统因素改变后，如果会迫使玩家学习新的判断方式，它就可能成为挑战维度。AI-Agent 辅助实现时，第一版原型可以做 2～3 个递进挑战。

1. 列出因素

  • 风向、风力、阵风
  • 浪高、浪向、洋流
  • 礁石大小、数量、分布
  • 能见度、航道宽度、时间压力

2. 筛选变量

  • 它是否改变玩家决策？
  • 它是否能被玩家感知？
  • 它是否改变行动反馈？
  • 它是否对应真实领域能力？

3. 组合挑战

  • 逆风 + 开阔水域
  • 横向洋流 + 窄航道
  • 密集礁石 + 变风
  • 低能见度 + 弱风 + 时间限制

4. 对应能力

  • 读风与调帆
  • 提前补偿航线
  • 路线规划与风险判断
  • 谨慎探索和优先级判断

单变量挑战

稳定侧风：先让玩家理解风向、帆角和船速的关系。

→

双变量组合

逆风目标：玩家必须通过之字航行规划路线。

→

环境冲突

礁石风道：安全路径和风向条件互相冲突。

→

综合任务

雾中返航：低能见度、弱风、洋流和时间限制叠加。

研究观察点

DOMAIN-clear领域和学习情境足够具体
NOVICE-clear新手误解被明确识别
EXPERT-clear高手判断方式被表达
FB-clear领域反馈转成游戏反馈
SKILL-loop形成观察-行动-反馈-调整循环
THEME-skin题材换皮，机制没有领域思维
CHAL-combo挑战来自变量组合
CHAL-curve挑战形成学习曲线
CHAL-random挑战是随意想法，不来自系统
