首次对话协议Kickoff Prompt

你在 AI IDE 里跟 Agent 说的第一句话，决定了后面两三个小时的走向。这份协议做三件事：先让 AI 把工作空间 index 一遍（它必须真的读过 brief.md、system-graph.png 和 generate-development-log-prompt.md），复述它理解的设计（你说"对"之前它不许写代码），以及要求第一版 demo 和第一版网页同时交付。The first thing you say to your agent decides the next few hours. This protocol does three things: make AI index the workspace first (it must actually read brief.md, system-graph.png, and generate-development-log-prompt.md), make it restate the design back to you (no code until you say yes), and require the first demo and the first version of the site to ship together.

  1. Export brief.md from the Session 2 workbook, save your system graph as system-graph.png, and download generate-development-log-prompt.md.
  2. Create an empty folder, drop all three files in, and open that folder in your AI IDE.
  3. Copy the entire kickoff prompt below and send it to your AI. AI lists the files, reads all three files (including the log prompt), then restates the design back to you.
  4. Once you confirm it understood, say go.

为什么要多这一步：跳过 index 的 AI 会直接开始写"一个看起来像游戏的东西"，用的是它自己的想象，不是你的领域。复述这一步是你在接管设计权。Why this extra step: an AI that skips indexing starts writing "something that looks like a game" out of its own imagination instead of your domain. Restating the design back to you is how you take the design authority back.

提示词全文The prompt

点击复制，原样粘贴给 AI Agent，不要删改。Click copy and paste it to your agent verbatim — do not edit it.

You are my AI development collaborator for a course project called "Game Design from Everyday Life" (CGDD). We are building a small browser game out of a domain I personally know.

This folder already contains three files I made myself:

- brief.md — the 16-section development brief I exported from the course workbook. It is the specification. Treat it as the source of truth.
- system-graph.png — my system graph, drawn by hand.
- generate-development-log-prompt.md — the protocol that tells you how to maintain agent-development-log.md. Follow it whenever you write a log entry.

Do the following in order. Do not skip ahead and do not write code until I tell you to.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 0 — INDEX THE WORKSPACE

1. List every file and folder in this project directory.
2. Read brief.md in full.
3. Read system-graph.png. If you cannot read images, say so plainly and ask me to describe it instead of guessing.

Then report back:

- Files you found
- The domain, the core learning shift, the core mechanic, the main data, and the challenge presets — each quoted directly from brief.md, not paraphrased
- Anything in brief.md that is empty, missing, or contradicts something else in it

STOP after this report. Do not propose a plan. Do not write code.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 1 — RESTATE THE DESIGN IN YOUR OWN WORDS

In under 200 words: what the player does, what they are supposed to learn, which data changes when they act, which feedback teaches them, and how the challenge presets differ from one another.

If any of these is missing from brief.md, stop and ask me. Do not fill the gap with your own invention — an invented mechanic is worse than a missing one, because I may not notice.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 2 — PROPOSE THE PROJECT SPACE

Show me the folder structure you intend to create, and the pages the website will have.

The website is the project space, not a final report and not a marketing page. It must exist from the first milestone and be updated at every milestone after that.

Required from day one:

- index.html — home: designer statement, system graph, and the play link
- game.html — the playable game
- process.html — the human-AI development timeline
- assets/ — JS/CSS, system graph image, audio, fonts
- development-log/agent-development-log.md
- README.md — how to run it, controls, dependency track, main variables

Every internal link and asset path must be relative. This project will be published with GitHub Pages from a repository subpath, so any path beginning with "/" will break on the live site even though it works locally.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 3 — DEFINE THE FIRST MILESTONE, THEN SHIP BOTH

Define the smallest complete version that proves the core loop. Then deliver BOTH of these in the same pass:

(a) a playable demo — one full observe → judge → act → feedback → adjust loop, and 2-3 challenge presets when brief.md defines them
(b) the first real version of index.html — actual content, not a placeholder or a "coming soon" page

Do not deliver the demo without the page, and do not deliver the page without the demo.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

STEP 4 — WAIT FOR MY CONFIRMATION

Stop here. Show me what you found in STEP 0, your restatement, your proposed structure, and your first-milestone plan. Wait until I say go before writing any code.

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

RULES FOR EVERYTHING AFTER

- Keep the website current. When the design changes, the website changes with it. A site that describes an older version of the game is worse than no site.
- Never invent design decisions on my behalf. If brief.md does not say, ask me.
- If you are about to make the game more generic — score attack, timer pressure, or difficulty sliders instead of genuinely different constraints — stop and tell me before you do it.
- After every meaningful change, append a Raw Interaction Log to development-log/agent-development-log.md. When I say "reflect on this stage," draft the Reflection Log but leave the Required Student Reflection for me to answer.
- The repository is public. Never write passwords, tokens, or API keys into any file.
按 ⌘/Ctrl+C 也可以手动复制。You can also select the text and press ⌘/Ctrl+C.

三条约束分别防什么What each constraint prevents

设计DESIGN为什么这么写Why it is written this way

  • STEP 0 先 indexSTEP 0 — index first — 防止 AI 不看你的 brief 就开始写。没有这一步，它做出来的是一个"通用小游戏套了个主题"，而你可能到很晚才发现。Stops AI from writing code before it has read your brief. Without this step you get a generic mini-game wearing your domain as a skin, and you may not notice until late.
  • STEP 1 先复述STEP 1 — restate first — 这是你接管设计权的时刻。它复述的内容里如果出现了你没写过的东西，那就是它在替你设计——当场纠正，比改代码便宜得多。This is where you take design authority back. If its restatement contains something you never wrote, it is designing for you. Catching that now is far cheaper than fixing code later.
  • STEP 3 一起交付STEP 3 — ship both — 防止"游戏做完了，网页最后补"。展示页是项目空间，不是总结报告；它必须从第一天就存在，并跟着设计一起长。等到最后补，它只会变成一份跟实际游戏对不上的漂亮文档。Stops the "game done, website later" trap. The site is the project space, not a wrap-up report. Bolted on at the end, it becomes a polished document that no longer matches the actual game.
判断标准：AI 可以写所有代码，但它必须先证明自己读懂了你，才配动手。The rule: AI may write all the code, but it has to prove it understood you before it is allowed to start.

边界：谁决定什么Boundary: who decides what

✋ 你决定✋ You decide

  • 确认 AI 复述的设计是对的（STEP 1 之后说"对"或"不对"）。
  • brief.md 里没写的，由你回答，不是 AI 补。
  • AI 提出"要不要加个计分/计时/难度滑块"时，由你判断这算不算把游戏变普通。
  • 每个阶段的 Required Student Reflection。
  • Confirm the restated design is right (say yes or no after STEP 1).
  • Answer what brief.md left out — AI must not fill gaps for you.
  • Judge whether AI's "let's add a score / timer / difficulty slider" turns the game generic.
  • Write every Required Student Reflection yourself.

🤖 AI 做🤖 AI does

  • 列出并读完工作空间里的文件（STEP 0）。
  • 提出文件夹结构与网站页面计划（STEP 2）。
  • 写代码、调试、跑本地服务器。
  • 自动追加 Raw Interaction Log、维护相对路径。
  • List and read the workspace files (STEP 0).
  • Propose the folder structure and site page plan (STEP 2).
  • Write code, debug, run the local server.
  • Append Raw Interaction Logs automatically and keep paths relative.
