  2. 放入Session 2下载的Markdown、系统图PNG和开发日志提示词.md。
  3. 让AI Agent打开这个文件夹。
  4. 在 AI Agent 中将复制的首次对话协议prompt 发送（这是唯一需要手动发送的提示词，AI 会自动读取文件夹中的其他文件）。

  1. Create an empty project folder.
  2. Add the Session 2 Markdown, system graph PNG, and development log prompt.md.
  3. Open this folder with your AI Agent.
  4. Paste the copied kickoff prompt into your AI agent (this is the only prompt you need to send manually; AI will read the other files in the folder automatically).
  5. Confirm the Agent's restatement is right before allowing it to write code.
  6. Publish this folder as a public repo with GitHub Desktop (Pages requires a public repository), then add your instructor as a collaborator.

你需要发送的唯一提示词：首次对话协议——让 AI 先 index 工作空间、读完三份文件（含开发日志提示词），向你复述它理解的设计，并要求第一版 demo 和第一版 index.html 同时交付。你确认之前它不许写代码。

The only prompt you need to send: the kickoff prompt — makes AI index the workspace, read all three files (including the log prompt), restate the design back to you, and deliver the first demo together with the first index.html. It may not write code until you confirm.

重要：AI可以生成代码和建议，但不能替你决定游戏应该教什么、哪种挑战更有意义，也不能替你完成学生反思。

Important: AI can generate code and suggestions, but it cannot decide what the game should teach, which challenges are meaningful, or write the student reflection for you.

第三份文件：开发日志提示词The Third File: Development Log Prompt

这份 .md 文件 不需要你手动发送——它放在项目文件夹里，AI 读完 kickoff 后会自动读取并开始执行。但你应当了解它要求 AI 做什么，以及为什么这样设计。

This .md file does not need to be sent manually — it sits in the project folder and AI reads it automatically after kickoff. But you should understand what it asks AI to do, and why it is designed this way.

它产出什么What it produces

一个持续增长的 agent-development-log.md，按时间线记录整个开发过程。

A continuously growing agent-development-log.md that chronicles the entire development process.

两种记录Two types of entries

Raw Interaction Log — 每次有意义的对话后立即记录（你要求了什么、AI 做了什么、改了哪些文件）。

Raw Interaction Log — written immediately after every meaningful conversation (what you asked, what AI did, what changed).

Reflection Log — 每个里程碑结束时生成（完成了什么、AI 怎么影响方向、你自己做了哪些决定）。

Reflection Log — generated at each milestone (what was completed, how AI influenced direction, what decisions you made yourself).

四条关键护栏Four Key Guardrails

护栏Guardrail 作用Purpose
AI Design Assumptions 每次交互中，AI 必须列出它在你的原始需求之外自行做出的设计决策。防止 AI "悄悄加功能"。Every interaction, AI must list design decisions it made beyond your original request. Prevents AI from quietly adding features.
Student Independent Changes 每个反思阶段，你必须报告自己独立做了哪些改动（不通过 AI）。证明你在主动驾驶。Each reflection stage, you must report changes you made independently (without AI). Proves you are actively driving.
Concept Drift 如果设计方向发生了偏移，必须记录：原概念是什么、新概念是什么、AI 在其中扮演了什么角色。If the design direction drifted, record: original concept, new concept, and what role AI played in the shift.
Required Student Reflection 每个里程碑的最后一步——AI 不能代写。你必须亲自回答：游戏是否还表达了我最初的生活体验和核心情感？The final step of every milestone — AI cannot write this. You must answer: does the game still express my original life experience and core emotion?

为什么需要这份日志？这个课程的目标不是"做出一个游戏"，而是"理解人机协作设计是如何发生的"。日志是你期末展示的核心证据：它展示了你的设计判断、AI 的影响、以及你对设计方向的掌控力。没有日志的项目只是一个黑盒产物；有日志的项目是一个可研究的设计过程。

Why this log? This course's goal is not "make a game" but "understand how human-AI collaborative design happens." The log is your core evidence for the final exhibition: it shows your design judgment, AI's influence, and your control over the design direction. A project without a log is just a black-box product; a project with a log is a studyable design process.

Session OutcomesSession Outcomes

By the end of the session, your project is not only a game file. It is a complete set of materials that can be shown, continued, and studied.

发布与展览Publishing & Exhibition

项目结束时不需要打包 ZIP。你的仓库本身就是提交物，GitHub Pages 会把它变成一个任何人都能打开的可玩链接——这也是期末小展览的入口。

There is no ZIP to package. Your repository is the submission, and GitHub Pages turns it into a playable link anyone can open — the entry point for the end-of-module exhibition.

  1. 让AI Agent说明所选依赖Track和理由。
  2. 如使用npm/Vite，先执行生产构建，把静态输出放到仓库根目录。
  3. 确认所有页面使用相对路径——Pages 部署在子路径下，绝对路径会 404。
  4. 用本地静态HTTP服务器跑一遍，逐个测试导航、游戏、控制、挑战和胜负。
  5. 在1920×1080窗口进行最终展示测试。
  6. 确认没有提交密码、API Key、node_modules、缓存或临时文件。
  7. 开启 GitHub Pages：Settings → Pages → Deploy from a branch → main / (root)。
  8. 等几分钟，打开线上链接再测一遍，然后把链接和仓库地址交给老师。
  1. Ask the AI Agent to state the selected dependency track and reason.
  2. If using npm/Vite, run the production build and put the static output at the repository root.
  3. Confirm every page uses relative paths — Pages serves from a subpath, so absolute paths 404.
  4. Serve the project through a local static HTTP server and test navigation, the game, controls, challenges, win and loss.
  5. Test the exhibition view at 1920×1080.
  6. Confirm no passwords, API keys, node_modules, caches, or temporary files are committed.
  7. Turn on GitHub Pages: Settings → Pages → Deploy from a branch → main / (root).
  8. Wait a few minutes, re-test the live URL, then send the link and the repository URL to your instructor.
repository/                  ← GitHub Pages 根目录

├── game.html                # 可玩游戏
├── process.html             # 人机开发时间线
├── assets/                  # JS/CSS、系统图、音频、字体
├── development-log/
│   └── agent-development-log.md
├── brief.md                 # 开发规格（你从 Workbook 导出）
├── system-graph.png
├── ratings.csv              # 问题评分（教学反馈用）
├── README.md                # 运行方法、操作、依赖、主要变量
└── source/                  # 仅 Track C：src/、package.json

公开性提醒：GitHub Pages 在免费方案下要求仓库是 public 的。这意味着 brief.md、ratings.csv、development-log/ 和 commit 时间线都会被公开看到。不想公开的内容就不要放进仓库。同时绝对不要提交密码、API Key 或 node_modules。

Public by design: GitHub Pages requires a public repository on the free plan. That means brief.md, ratings.csv, development-log/, and the commit timeline are all publicly visible. Anything you do not want published simply stays out of the repository. And never commit passwords, API keys, or node_modules.
