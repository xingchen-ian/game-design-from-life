你将把Session 2的开发摘要和系统图交给AI Agent，共同建立项目网站、实现可玩游戏、测试挑战，并留下真实的开发记录。

Give your Session 2 development brief and system graph to an AI Agent. Together, you will build the project website, implement a playable game, test challenges, and preserve an honest development record.

建好文件夹、放入上面三个文件后，打开 首次对话协议，整段复制给 AI。可与开发日志提示词在同一条消息中同时发送。

Working PipelineWorking Pipeline

每个阶段都包含AI的开发工作和学生的设计判断。只有当两者都完成，项目才进入下一阶段。

Every stage combines Agent development work with student design judgment. Move forward only after both are complete.

准备项目输入Prepare Project Inputs

学生Student

建立项目文件夹，放入开发摘要、系统图和开发日志提示词。Create the project folder and add the brief, graph, and development log prompt.

AI Agent

读取三份文件，检查缺失和矛盾。Read all three files and identify missing or conflicting information.

确认实现计划Confirm the Build Plan

AI Agent

复述学习转变、核心循环、变量、反馈、挑战和网站结构。Restate the learning shift, loop, variables, feedback, challenges, and site structure.

学生Student

纠正误解并批准第一步，不要直接接受错误方向。Correct misunderstandings and approve the first step.

建立网站与记录Create the Site and Log

AI Agent

创建网站导航、页面结构、README和agent-development-log.md。Create navigation, page structure, README, and agent-development-log.md.

学生Student

检查网站是否准确表达创意和领域知识。Check whether the site accurately presents the idea and domain knowledge.

实现最小核心循环Build the Minimum Core Loop

AI Agent

实现观察、判断、行动、反馈和调整的完整闭环。Implement one complete observe, judge, act, feedback, and adjust loop.

学生Student

试玩并判断它是否真的训练预期能力。Play it and judge whether it teaches the intended ability.

增加挑战并迭代Add Challenges and Iterate

AI Agent

实现2–3个变量组合不同的挑战，并测试胜负与反馈。Implement 2–3 variable-based challenges and test outcomes and feedback.

学生Student

比较挑战，决定保留、修改或删除什么。Compare challenges and decide what to keep, change, or remove.

反思并更新项目Reflect and Update

AI Agent

更新网站、开发时间线、README和最终测试状态。Update the site, timeline, README, and final test status.

学生Student

亲自完成阶段反思，说明AI影响和自己的决定。Write the stage reflection, including AI influence and personal decisions.

发布并检查Publish and Verify

AI Agent

检查相对路径、隐私和文件完整性，确认本地静态服务器下一切正常。Check relative paths, privacy, and completeness; verify everything on a local static server.

学生Student

开启 GitHub Pages，打开线上链接最终试玩，把链接交给老师。Turn on GitHub Pages, do a final playtest on the live URL, and send the link to your instructor.

Session OutcomesSession Outcomes

Session结束时，项目不只是一个游戏文件，而是一套可以展示、继续开发和研究其过程的完整材料。

By the end of the session, your project is not only a game file. It is a complete set of materials that can be shown, continued, and studied.

项目网站Project Website

包含创意、领域知识、系统设计、开发过程和游戏入口。Idea, domain knowledge, system design, process, and game access.

可玩游戏Playable Game

一个完整核心循环和2–3个递进挑战。One complete core loop and 2–3 progressive challenges.

开发日志Development Log

按时间记录重要交互、失败、测试、决定和反思。Chronological interactions, failures, tests, decisions, and reflections.

源文件与素材Source and Assets

HTML、CSS、JavaScript、系统图、图片和声音。HTML, CSS, JavaScript, graph, images, and sounds.

README

运行方法、操作方式、文件结构、依赖和已知问题。Run instructions, controls, structure, dependencies, and known issues.

学生反思Student Reflection

哪些决定属于学生，AI如何影响方向，游戏是否仍表达原目标。Student decisions, AI influence, and fidelity to the original goal.

展览链接Exhibition Link

一个 GitHub Pages 网址，任何人打开就能玩，也是期末小展览的入口。One GitHub Pages URL anyone can open and play — the entry point for the end-of-module exhibition.

发布与展览Publishing & Exhibition

项目结束时不需要打包 ZIP。你的仓库本身就是提交物，GitHub Pages 会把它变成一个任何人都能打开的可玩链接——这也是期末小展览的入口。

There is no ZIP to package. Your repository is the submission, and GitHub Pages turns it into a playable link anyone can open — the entry point for the end-of-module exhibition.

  1. 让AI Agent说明所选依赖Track和理由。
  2. 如使用npm/Vite，先执行生产构建，把静态输出放到仓库根目录。
  3. 确认所有页面使用相对路径——Pages 部署在子路径下，绝对路径会 404。
  4. 用本地静态HTTP服务器跑一遍，逐个测试导航、游戏、控制、挑战和胜负。
  5. 在1920×1080窗口进行最终展示测试。
  6. 确认没有提交密码、API Key、node_modules、缓存或临时文件。
  7. 开启 GitHub Pages：Settings → Pages → Deploy from a branch → main / (root)。
  8. 等几分钟，打开线上链接再测一遍，然后把链接和仓库地址交给老师。
  1. Ask the AI Agent to state the selected dependency track and reason.
  2. If using npm/Vite, run the production build and put the static output at the repository root.
  3. Confirm every page uses relative paths — Pages serves from a subpath, so absolute paths 404.
  4. Serve the project through a local static HTTP server and test navigation, the game, controls, challenges, win and loss.
  5. Test the exhibition view at 1920×1080.
  6. Confirm no passwords, API keys, node_modules, caches, or temporary files are committed.
  7. Turn on GitHub Pages: Settings → Pages → Deploy from a branch → main / (root).
  8. Wait a few minutes, re-test the live URL, then send the link and the repository URL to your instructor.
repository/                  ← GitHub Pages 根目录
├── index.html               # 首页：设计者陈述、系统图、开始游戏
├── game.html                # 可玩游戏
├── process.html             # 人机开发时间线
├── assets/                  # JS/CSS、系统图、音频、字体
├── development-log/
│   └── agent-development-log.md
├── brief.md                 # 开发规格（你从 Workbook 导出）
├── system-graph.png
├── ratings.csv              # 问题评分（教学反馈用）
├── README.md                # 运行方法、操作、依赖、主要变量
└── source/                  # 仅 Track C：src/、package.json

公开性提醒：GitHub Pages 在免费方案下要求仓库是 public 的。这意味着 brief.md、ratings.csv、development-log/ 和 commit 时间线都会被公开看到。不想公开的内容就不要放进仓库。同时绝对不要提交密码、API Key 或 node_modules。

Public by design: GitHub Pages requires a public repository on the free plan. That means brief.md, ratings.csv, development-log/, and the commit timeline are all publicly visible. Anything you do not want published simply stays out of the repository. And never commit passwords, API keys, or node_modules.

开始开发Start Development

  1. 新建一个空项目文件夹。
  2. 放入Session 2下载的Markdown、系统图PNG和开发日志提示词.md。
  3. 让AI Agent打开这个文件夹。
  4. 同时发送首次对话协议和开发日志提示词（可在同一条消息中发送）。
  5. 先确认Agent复述的设计是对的，再允许它开始写代码。
  6. 用 GitHub Desktop 把这个文件夹发布成 public repo（Pages 需要公开仓库），并把老师加为 collaborator。
  1. Create an empty project folder.
  2. Add the Session 2 Markdown, system graph PNG, and development log prompt.md.
  3. Open this folder with your AI Agent.
  4. Send both the kickoff prompt and the development log prompt together (in a single message).
  5. Confirm the Agent's restatement is right before allowing it to write code.
  6. Publish this folder as a public repo with GitHub Desktop (Pages requires a public repository), then add your instructor as a collaborator.

第一条：首次对话协议——让 AI 先 index 工作空间、读完三份文件，向你复述它理解的设计，并要求第一版 demo 和第一版 index.html 同时交付。你确认之前它不许写代码。

First: the kickoff prompt — makes AI index the workspace, read all three files, restate the design back to you, and deliver the first demo together with the first index.html. It may not write code until you confirm.

第二条（可与第一条同消息发送）：开发日志提示词——让 AI 在帮你开发的同时维护 development-log/agent-development-log.md：它自动写交互记录，里程碑时停下来问你写阶段反思。下载 .md →

Second (can be sent in the same message): the development log prompt — while building, AI maintains development-log/agent-development-log.md: it writes interaction logs automatically and stops at milestones for your reflection. Download .md →

重要：AI可以生成代码和建议，但不能替你决定游戏应该教什么、哪种挑战更有意义，也不能替你完成学生反思。

Important: AI can generate code and suggestions, but it cannot decide what the game should teach, which challenges are meaningful, or write the student reflection for you.
